# server/src

后端的源码。六块:进程装配(`main.rs`)、库门面(`lib.rs`)、错误映射(`error.rs`)、
上游 gRPC 的翻译(`bangdream.rs`)、对象存储客户端(`objects.rs`,听过的歌存进 RustFS)、HTTP 处理函数(`routes/`),以及三个按职责分的子目录。

- `gate/`:请求进门那一道 —— token 换成账号、限流。
- `store/`:自家数据的家 —— 连接池与迁移、账号、本地歌单、播放事件、平台曲目缓存。
- `syncplay/`:遥控的信令 —— 接入、设备名册、控制权(目录名是已删的同播留下的)。

不负责客户端的任何东西:线上格式的形状在 `crates/contract`,那是两侧共同的契约。
也不负责平台数据的真相 —— 那在上游,这一层只翻译与缓存(`docs/adr/0016`、`0018`)。

路由表留在 `main.rs`,不进 `lib.rs`:它是这个进程的装配方式,不是可复用的库。
为什么单独立一个 lib、以及各块之间的分工,见 `server/README.md` 与 `lib.rs` 开头。
