# routes/play

一首歌的音频怎么交到客户端手上。三条路共用同一条上游取源,各要各的档位
(`docs/adr/0034`):播放要最高、缓存要无损、下载要 320k。

- `play.rs`(上一级):`GET /play/{id}`,交出一条客户端自己去取的链接 ——
  桶里有无损的给对象存储的签名链接,否则按最高档给网易云的临时直链。
- `download.rs`:`GET /download/{id}`,把字节拉过来、归一成 mp3 交出去。
- `archive.rs`:曲目以无损存进对象存储(#126、#147)—— 怎么存、`/play` 优先从这里
  交付、定时清掉哪都不在且三天没播的、空间上限的取舍、统计入口。
- `prefetch.rs`:预取队列的入口与后台 worker(#147)—— 歌单、日推、`/played`
  把该存的排进队列,worker 按音源限并发、限速地取来存进桶。
- `links.rs`:网易云直链的短期缓存(#139)—— 同一账号同一首,剩余有效期还够
  放完整首时复用上一次那条,不再问上游。只在内存里。

不负责对象存储怎么连(`server::objects`)和账目怎么落库(`server::store::archive`),
也不负责起播上报本身(`routes/library/history.rs`,它只是在报完之后调一下这里)。
