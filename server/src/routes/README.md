# routes

HTTP 的处理函数,按资源分。路由表本身在 `main.rs` —— 它是进程的装配方式,
不是可复用的库。

- `catalog/`:平台那边的东西 —— 搜索、歌词、曲目缓存、网易云账号绑定。
- `library/`:「我的库」—— 红心、本地歌单、播放历史。
- `queue/`:持久播放队列 —— 发布版本、按固定 revision 分页读、待应用的播放
  意图、播放端的执行报告(`docs/adr/0031`)。曲目数据走这里而不是信令,
  因为它的体积随用户的歌单长度增长。
- 根下:鉴权(`auth`)、起播与下载(`play/`)、应用内升级的安装包转发(`apk`),
  以及路由测试共用的夹具(`testing`)。

不负责数据本身:自家的在 `store/`,平台的真相在上游。这一层只管 HTTP 的形状 ——
状态码、请求体、响应体,以及把失败翻成 `contract::ErrorDto`。

`testing` 留在根:三处子目录的 `tests.rs` 都用它,放进任何一组都会让另一组反向依赖。
