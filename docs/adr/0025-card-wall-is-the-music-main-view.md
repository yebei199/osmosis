# 卡墙是音乐页主视图,列表是同一批卡塌回零深度

日期:2026-08-11。状态:已采纳,实现挂 issue #66,落地前音乐页保持列表。

## 背景

改版前音乐页是一列可滚的曲目行,3D 只存在于播放页的点云。改版要把「Slint UI +
Bevy 3D 同一块显存」这条架构主线开进挑歌环节:曲目封面本身成为 3D 场景里的
物体。第一个要定的问题是卡墙与列表的关系:两个页面,还是一个东西的两种摆法。

## 决策

- **卡墙是音乐页的主视图**,默认呈现,每次开局回卡墙,视图选择不持久化。
- **列表与卡墙是同一批卡**:切到列表是全部卡插值回零深度排成行(420ms),
  切回是重新散开。没有页面切换,没有第二份数据,选中态与滚动位置天然共享。
- **交互**:拖动往任意方向平移整场(惯性 + 阻尼,松手自由停),滚轮等同
  竖着划一下,点一下浮起高亮、**再点一下同一张就播放**并以相机 dolly 进
  播放页。3D 是一条贯穿的深度轴,从挑歌到沉浸不换世界。
  播放挂在普通点按上而不是双击:**触摸屏收不到双击**。Slint 每次触摸抬起都
  在 `Released` 之后补一个 `MouseEvent::Exit`,窗口发现顶层元素变了就清掉连击
  计数,`double-clicked` 因此一次也发不出来(2026-08-31 在努比亚平板上定位)。
  鼠标的双击照旧能播,它走得到那条回调。
- **网格是环面**:两轴都按周期取模,往任何方向拖到底都会回到同一批卡 ——
  卡墙没有边。每张卡仍只有一个实体,回绕发生在「卡相对镜头的位置」上。
  **回绕必须在屏幕外发生**,否则就是抖动:因此整场姿态角只转卡片朝向、不转
  卡片位置(旋转会把回绕轴混进深度),周期按最远那层卡上的视口算,竖向绕
  相机中心回绕。墙因此比一屏三行的老版式稀疏,这是无限滚动的代价。
- **布局按容器尺寸计算**,列距行距不写死像素;行列数按场区长宽比分配,周期
  由上一条的回绕要求定;竖视口相机后撤(`pullback`,与 `docs/adr/0007` 的
  版式判据配合)。设计稿的 204/136 列行距降为下限,实际间距多由周期撑开。
- **正在放的那一张走闪卡材质**(`render3d::foil`):彩虹干涉条纹加一道扫光,
  常驻缓慢流动。闪光是「在播」的视觉信号,不是装饰,因此只有一张卡会闪。
- **卡面的软边只在桌面上有**:安卓被 Adreno 逼着走 alpha 测试(见 adr/0012,
  2026-08-30 在努比亚平板上复验坑仍在),投影与圆角软边随之消失。两端共用
  同一份几何与烘焙,不同的只有透明度那一档。
- **无 GPU 的构建退回列表视图**(web / iOS 默认构建),与点云在同一条路径上
  静默降级,不报错。

## 备选方案

**列表默认,卡墙作为一个可切的「3D 模式」**。不选:模式意味着两套并列实现,
卡墙沦为演示品,没人会天天开一个模式;主线架构的卖点必须是默认路径。

**卡墙做成独立页面,与列表并列在导航里**。不选:两个页面就是两份状态,
「我刚才选到哪首」在切换时丢失,而且导航位是稀缺的。

## 代价

- 这是改版里最重的一步:动页面装配、相机、Slint 与 Bevy 的深度协作,压轴做。
- 封面卡成为场景物体后,列表滚动性能与虚拟化(`ListView`)要和 3D 卡的
  生命周期对齐,超出视野的卡何时卸载是新问题。
- 低端 GPU 上一面几十张纹理卡的墙有实测成本,布局参数(卡数、深度范围)
  要在真机上调,设计稿数值只是起点。
