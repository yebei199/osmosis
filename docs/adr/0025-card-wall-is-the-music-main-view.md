# 卡墙是音乐页主视图,列表是同一批卡塌回零深度

日期:2026-08-11。状态:已采纳,实现挂 issue #66,落地前音乐页保持列表。

## 背景

改版前音乐页是一列可滚的曲目行,3D 只存在于播放页的点云。改版要把「Slint UI +
Bevy 3D 同一块显存」这条架构主线开进挑歌环节:曲目封面本身成为 3D 场景里的
物体。第一个要定的问题是卡墙与列表的关系:两个页面,还是一个东西的两种摆法。

## 决策

- **卡墙是音乐页的主视图**,默认呈现,每次开局回卡墙,视图选择不持久化。
- **列表与卡墙是同一批卡**:切到列表是全部卡插值回零深度排成行(420ms),
  切回是重新散开。没有页面切换,没有第二份数据,选中态与滚动位置天然共享。
- **交互**:拖动整场旋转平移(惯性 + 阻尼,松手吸附格点),滚轮沿 z 推拉,
  单击浮起高亮,双击播放并以相机 dolly 进播放页。3D 是一条贯穿的深度轴,
  从挑歌到沉浸不换世界。
- **布局按容器尺寸计算**,列距行距不写死像素;竖视口相机后撤(`pullback`,
  与 `docs/adr/0007` 的版式判据配合)。
- **无 GPU 的构建退回列表视图**(web / iOS 默认构建),与点云在同一条路径上
  静默降级,不报错。

## 备选方案

**列表默认,卡墙作为一个可切的「3D 模式」**。不选:模式意味着两套并列实现,
卡墙沦为演示品,没人会天天开一个模式;主线架构的卖点必须是默认路径。

**卡墙做成独立页面,与列表并列在导航里**。不选:两个页面就是两份状态,
「我刚才选到哪首」在切换时丢失,而且导航位是稀缺的。

## 代价

- 这是改版里最重的一步:动页面装配、相机、Slint 与 Bevy 的深度协作,压轴做。
- 封面卡成为场景物体后,列表滚动性能与虚拟化(`ListView`)要和 3D 卡的
  生命周期对齐,超出视野的卡何时卸载是新问题。
- 低端 GPU 上一面几十张纹理卡的墙有实测成本,布局参数(卡数、深度范围)
  要在真机上调,设计稿数值只是起点。
