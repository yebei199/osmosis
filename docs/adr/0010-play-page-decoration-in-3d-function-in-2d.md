# 播放页:装饰入 3D、功能留 2D

日期:2026-07-28。状态:已采纳。

## 背景

播放页(见 `CONTEXT.md`)是本仓库第一个可视化表面。
[`docs/note/visualization-surface-and-audio.md`](../note/visualization-surface-and-audio.md)
已论证:通用 UI 做深度是负收益,播放页是深度 UI 唯一说得通的落点,且本项目的结构性
优势正在于 UI 像素与 3D 像素同一合成体系(参照物 Mineradio/projectM 的可视化永远只是
UI 后面的一块矩形,两层互不知情)。问题是这个优势用到哪一档。

## 决策

播放页的元素按职责分进两个世界,边界不可含糊:

- **装饰入 3D。** 封面、歌名、歌词(将来)、频谱仪表这类元素作为有深度的空间卡片
  活在 bevy 场景里,粒子可以从它们前后穿过。遮挡复用 render3d 既有的双图设施
  (场景 + 遮挡层,见 `crates/render3d/README.md`),不新建管线。
- **功能留 2D。** 播放/暂停/切歌/进度等一切操作类控件留在最上层的 2D 玻璃层
  (常驻控制条),永远可预测、永远点得到,不参与遮挡。
- **不可破坏的前提:** 装饰层可以被遮挡,是因为被遮挡的信息在别处有等价路径。
  任何把「只能在播放页 3D 里完成的操作」加进来的改动,都在推翻本决策的前提,
  必须先回到这里改决策。

### 歌词是例外(2026-08-01 补)

上面把歌词列进了「粒子可以前后穿过」的那一档。那是个**错误的例子**,不是前提
出了问题:歌词在别处**没有**等价路径 —— 它只在播放页存在,被盖住就是读不到。
按同一条前提,它本来就不该被遮挡。

做法是**把歌词卡抬到位移峰值之上**(当时那个常量叫 `CARD_ANCHOR`,z 从 0.9 抬到
1.8):粒子一颗不少、照旧起伏,只是全都从字后面走。

后来歌词干脆改成与歌名同层、画在粒子之上,那个常量也就不再是「卡片挂哪」而只是
「点云放哪」,2026-08-13 拆成了 `CLOUD_ORIGIN`,卡片的锚点另立
`CARD_ANCHOR_LOCAL`(见下面那节补记)。

曾经试过另一条路:让粒子按歌词块的包围盒绕开。**不选** —— 那个盒是整行宽的,
推开之后点云里横贯一条空带,比被遮挡更难看(实测过,已回退)。

封面、歌名这些仍然照旧穿过 —— 它们在列表、控制条上都有等价路径。

### 深度卡片现在是标注卡(2026-08-13 补)

歌词退出深度合成之后,这套机关空转了两周:`needs_occluder` 恒假,那台相机从没醒过。
现在挂上去的是**世界空间标注卡**,内容是曲名。它守得住本 ADR 的前提:曲名在列表、
控制条、以及它下方的歌名行都有等价路径,被粒子挡住一半也丢不了信息。

**被标注的是场景里新加的一枚方块,不是封面点云。** 先试的是点云:锚点写进它的局部
坐标,拖动自转时卡片跟着甩。真机上卡片一像素都看不见 —— 锚点落在封面平面上,半数
粒子比它更近、全被画进遮挡层。也无解:要卡片读得成,锚点得高过粒子位移峰值 1.2~1.5;
要它刚性挂在点云上还留在画面里,它到旋转中心的距离又不能超过竖屏可见半宽 1.156。

这条经验值得留在本 ADR 里,因为它是「装饰在 3D」这个决定的边界条件:**深度正确的 UI
需要一个有深度的对象,而不只是一个有深度的场景**。三万颗无特征粒子是场景不是对象。
播放页因此多了一枚绕轨道慢转的方块 —— 它是这条产品线(数字孪生)的第一个被标注物,
也是遮挡这件事第一次真的演出来。

代价量过了:第二遍全场景绘制每帧 +2.4ms(+22%),数据在 `crates/render3d/README.md`。

## 备选方案

**3D 只当背景。** 普通 Slint 页叠在粒子矩形上,UI 与粒子互不遮挡。最稳,但那就是
Mineradio 的形状 —— 放弃了本项目唯一拿得到、而对照物结构上拿不到的东西。**不选**。

**全部入 3D。** 连操作控件也是场景里的物体。最激进,但「暂停键被粒子挡住点不到」
会真实发生,等价路径前提被破坏,可预测性无从谈起。**不选**。

## 代价

- 每个新播放页元素都要先过一道归属判断(装饰还是功能),边界元素(比如可点击的
  歌词行)会引发讨论 —— 这是本 ADR 存在的原因:判据写死,讨论有锚点。
- 深度卡片依赖 bevy-3d feature;无 bevy 的端(web/ios 默认构建)播放页停留在
  「2D 卡片 + warp 背景」形态,同一页面在不同端呈现档位不同。
