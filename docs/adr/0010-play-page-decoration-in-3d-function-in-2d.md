# 播放页:装饰入 3D、功能留 2D

日期:2026-07-28。状态:已采纳。

## 背景

播放页(见 `CONTEXT.md`)是本仓库第一个可视化表面。
[`docs/note/visualization-surface-and-audio.md`](../note/visualization-surface-and-audio.md)
已论证:通用 UI 做深度是负收益,播放页是深度 UI 唯一说得通的落点,且本项目的结构性
优势正在于 UI 像素与 3D 像素同一合成体系(参照物 Mineradio/projectM 的可视化永远只是
UI 后面的一块矩形,两层互不知情)。问题是这个优势用到哪一档。

## 决策

播放页的元素按职责分进两个世界,边界不可含糊:

- **装饰入 3D。** 封面、歌名、歌词(将来)、频谱仪表这类元素作为有深度的空间卡片
  活在 bevy 场景里,粒子可以从它们前后穿过。遮挡复用 render3d 既有的双图设施
  (场景 + 遮挡层,见 `crates/render3d/README.md`),不新建管线。
- **功能留 2D。** 播放/暂停/切歌/进度等一切操作类控件留在最上层的 2D 玻璃层
  (常驻控制条),永远可预测、永远点得到,不参与遮挡。
- **不可破坏的前提:** 装饰层可以被遮挡,是因为被遮挡的信息在别处有等价路径。
  任何把「只能在播放页 3D 里完成的操作」加进来的改动,都在推翻本决策的前提,
  必须先回到这里改决策。

## 备选方案

**3D 只当背景。** 普通 Slint 页叠在粒子矩形上,UI 与粒子互不遮挡。最稳,但那就是
Mineradio 的形状 —— 放弃了本项目唯一拿得到、而对照物结构上拿不到的东西。**不选**。

**全部入 3D。** 连操作控件也是场景里的物体。最激进,但「暂停键被粒子挡住点不到」
会真实发生,等价路径前提被破坏,可预测性无从谈起。**不选**。

## 代价

- 每个新播放页元素都要先过一道归属判断(装饰还是功能),边界元素(比如可点击的
  歌词行)会引发讨论 —— 这是本 ADR 存在的原因:判据写死,讨论有锚点。
- 深度卡片依赖 bevy-3d feature;无 bevy 的端(web/ios 默认构建)播放页停留在
  「2D 卡片 + warp 背景」形态,同一页面在不同端呈现档位不同。
