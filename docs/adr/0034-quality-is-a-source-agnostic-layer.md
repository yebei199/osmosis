# 音质是与音源无关的一层,缓存存无损、播放要最高

日期:2026-09-26。状态:已采纳(#147)。

## 背景

播放与归档(#126)都写死在 320k(`PLAY_QUALITY = QualityLevel::High`),而这个档位
是 bang-dream 的 proto 枚举 —— 网易云的概念直接漏到了路由里。用户一直是网易云会员,
无损没用上。用户 2026-09-26 定了:缓存存无损,播放用最高音质,并且音质要独立于
音源,因为以后会接 B 站、抖音这类音源(`docs/adr/0033`)。

## 决策

`server::quality` 是一层与音源无关的模型:

- **档位**(`Tier`)是想要什么:`low` < `standard` < `high` < `lossless` < `hi_res`,
  有序。「最高」是 `Tier::HIGHEST`,要音源给出它能给的最好那一档。
- **实际音质**(`Quality`)是拿到的是什么:档位、格式、码率、位深、采样率。
  音源不报的位深与采样率是 `None`;存进桶的 FLAC 从文件头 STREAMINFO 读出来。
- **每个音源一份双向映射**(`quality/<音源>.rs`):通用档位翻成它的请求参数,它报回来
  的档位翻回通用档位。网易云经 bang-dream 的 `QualityLevel`,一一对应。
- **协商在音源那边**:请求一个档位,音源给它实际能给的最好一档,我们照它报回来的
  如实记、如实交给客户端(`PlaySourceDto.quality`,只加不改)。报回来的档位缺席时
  按格式与码率认,不按请求的档位冒充。

用在三处:

- **缓存**按 `lossless` 去要,只存实际至少是无损的那份。音源给不出无损(这首没有
  无损版本、或账号权限不够)就不存 —— 桶里存 320k 等于又回到了要清掉的那批。
- **`/play`** 先看桶里有没有无损,有就交桶里的;没有才去音源按「最高」现取。
- **`/download`** 仍按 `high` 要:它的产物一律是 320k mp3,要无损只是多转一次码。

## 备选方案

**直接把 `PLAY_QUALITY` 改成无损**。不选:路由仍认识网易云的枚举,接第二个音源时
每个调用点都要重新分辨「这是谁的档位」;而且播放与缓存要的本来就是两档。

**在 contract 里放档位枚举**。不选:contract 只放线上格式(`docs/adr/0001`),
档位在线上是一个字符串就够;枚举与映射是服务端自己的事。

**音源给不出无损时也存下它给的**。不选:桶里会重新长出 320k,验收要的是「桶里只有
无损」;这类歌每次播放多问一次音源,代价只是一次取链接。

## 后果

- 接新音源:在 `quality/` 加一个文件写映射,取源的地方按音源分派。本层与客户端不动。
- 旧的 320k 缓存(`stored_tracks.quality = 'high'`)由清扫任务连对象带账删掉。
- 客户端目前不读 `quality`,它是给日志、排查与以后的界面留的。
