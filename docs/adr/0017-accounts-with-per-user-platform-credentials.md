# 账号是自家的用户名密码,每个账号绑自己的网易云凭据

日期:2026-08-01。状态:已采纳。

## 背景

后端上了远端(`docs/adr/0015`),axum 面向网络,`docs/adr/0009` 刻意推迟的那道
门禁到了要补的时刻。同时,本地歌单与播放历史落了库,「这行数据是谁的」第一次
需要一个答案 —— 设备身份回答不了它:设备是「哪台」,不是「谁」。

## 决策

- **注册**:用户名 + 密码,外加一个部署时配置的邀请码 —— 公网可达但不对陌生人开门。
  密码 argon2 哈希落 Postgres。
- **会话**:登录签发不透明 token,存库、可单独吊销;客户端本地长期保存。
  不用 JWT:无法吊销单台设备的会话,对个人部署没有换来任何好处。
- **身份不外包给网易云**:不拿网易云登录当本应用的登录。账号的生命周期是自己的,
  网易云只是账号名下的一个绑定。
- **每个账号绑自己的网易云凭据**。axum 鉴权后把 user_id 放进每次 gRPC 调用的
  metadata,bang-dream 按它分片保存凭据与设备指纹(那侧的决策见 bang-dream
  `docs/adr/0009`)。扫码/验证码登录网易云因此是**每账号一次**的操作。
- 设备身份(`docs/adr/0009`)原样保留,与账号正交:账号回答「数据归谁」,
  设备回答「同播里推给哪台」。0009 推迟的「门禁」由本决策补上,其余不受影响。

## 备选方案

**全部设备共享一个预共享密钥,不建用户。** 0009 预言的第一道门禁形态。不选:
它挡得住陌生人,但回答不了「这行播放历史是谁的」—— 落库数据一旦有归属需求,
密钥就不够用了。

**JWT 无状态会话。** 不选,理由见上。

## 代价

- 客户端多一个登录页与首启流程;所有新路由都过鉴权中间件。
- 忘记密码没有找回通道(没有邮箱/短信依赖),只能运维手动重置 —— 个人部署可接受。
- bang-dream 的凭据模型从「全服务一份」变成「按用户一份」,是那侧的一次领域翻案。
