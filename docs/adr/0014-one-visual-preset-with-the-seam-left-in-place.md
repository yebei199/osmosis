# 视觉预设只留一档,那条 seam 留着

日期:2026-07-31。状态:已采纳。

## 背景

播放页曾有六档视觉预设:封面、滚筒、星球、虚空、唱片、星河。它们照着参照物的视觉
控制台做,是同一批粒子的不同摆法(见 `CONTEXT.md`「视觉预设」)。

真拿来听歌之后,除默认的「封面」之外都不好看:粒子离开封面平面之后,那张图就散了,
而点云存在的理由恰恰是「封面这张图的另一种呈现」。剩下五档把主体变成了装饰,
与它们服务的东西相抵触。

## 决策

- **只留「封面」一档。** 其余五档连同着色器里的 `place_tunnel` / `place_orbit` /
  `place_void` / `place_vinyl` / `place_wallpaper` 一并删掉,约 225 行 WGSL。
  没人走的分支没有测试守着,改周边代码时会静默腐烂,下次想用会发现早就编不过了 ——
  git 里随时找得回来,留在热路径上则要一直付维护费。
- **`preset` 那条 seam 留着。** `.slint` 的 `viz-preset` → `VizControls` →
  `VizFrame` → 着色器 uniform,整条不动,只是当前唯一的合法值是 0。
  `preset_index` 的越界兜底也留着:那是跨层输入的信任边界,与档位多少无关。
- **切换入口改成弹出式列表,只列一项。** 现在点它选中的就是已经选中的那一档 ——
  留着是因为加档时只需往列表里填,不必重新设计入口。
- **切换后浮现档位名的提示删掉。** 它是为「循环切换时不知道切到了哪一档」而设的;
  列表本身显示名字并高亮当前项,提示就多余了。

## 备选方案

**连入口一起删。** 只有一档就无可切换,一个永远只有一项的列表是空操作,控制簇也能
少一个键。不选:入口留着,加档时改动只落在列表数据上;删掉的话下次要连位置、层级、
交互重新想一遍,而那正是最容易反复的部分。

**留着五档的着色器分支,只拆 UI 入口。** 改主意时把列表填回去即可。不选,理由同上:
没有调用方的代码会腐烂,而它坐在每帧都要跑的顶点着色器里。

## 代价

- 现在点那个列表什么也不会发生。用户可能点两下才确信它不是坏了。
- 加回任何一档都要重写它的 `place_*`,不是把注释解开。
- `preset` 这条 seam 留着一个只有单值的参数,读代码的人会问它为什么存在 —— 本文件
  就是答案,`cloud.rs` 的 `PRESET_COUNT` 处指向这里。
