# 封面点云是 bevy 场景里的一个 mesh

日期:2026-07-30。状态:已采纳。相关 issue:#22。

## 背景

播放页的可视化主体换成**封面点云**(见 `CONTEXT.md`):封面按网格采样成三万多颗
粒子,颜色取自对应像素。原先那层浮空尘埃(1300 颗与封面无关的小球)一并拆除。

数量级变了两个数量级,原来的做法跟不上:尘埃层是 1300 个 bevy 实体,每帧在 CPU 上
逐个写 `Transform`,小米13 上 `app.update()` 已经 36.75ms/帧。三万多个实体不必试。

同时,`docs/adr/0010` 立过一条不可含糊的边界:装饰入 3D,粒子要能从封面卡与歌词
**前后穿过**。遮挡靠的是本 crate 的双相机设施(场景相机 + 只留「比卡片更近」片元的
遮挡相机,见 `crates/render3d/README.md`)。任何绕开 bevy 场景的画法都拿不到它。

## 决策

**点云是 bevy 场景里的一个 mesh,不是一堆实体,也不是一个独立的 wgpu pass。**

- **一个 mesh**:183×183 个朝向相机的小四边形烘进同一份顶点缓冲,每个顶点带
  格点 uv、四边形角偏移、逐粒子随机数。运动学全在顶点着色器里,CPU 每帧只更新
  几个 uniform(时间、三段电平、切歌进度、涟漪表)。一次 draw call。
- **自定义 `Material`**:走 bevy 的材质管线,于是自动同时进两台相机的渲染,
  遮挡设施免费复用,`docs/adr/0010` 不动。
- **网格 183×183**:原版 `coverResolution` 默认档 1.55 的换算结果(`round(118×1.55)`,
  钳进 88..=183)。观感基准照参照物的默认值定,不自创。

## 备选方案

**三万多个实体,逐帧写 Transform。** 与现在的尘埃层同构,改动最小。但 1300 颗已经
吃掉小米13 一帧的三分之一,线性外推是秒级 —— 不选。

**照 `warp.rs` 再起一个独立 wgpu pass。** 本 crate 已有两个这样的 pass(navglass、
warp),模板现成,不必碰 bevy 的材质管线,是最省事的写法。代价是点云从此活在 bevy
场景之外,拿不到深度缓冲,只能整层压在 UI 底下 —— 那正是 `docs/adr/0010` 判为
「Mineradio 的形状」而否掉的备选。省下的那点工,买的是放弃本项目唯一的结构优势。
**不选**。

**GPU 侧 compute 粒子。** 位置在 compute pass 里演化、写进 storage buffer。形态上更
远,也更贵:要自建渲染图节点,且与 `docs/note/animated-background-and-compute.md`
的 scatter 判据无关(点云的每颗粒子只读自己那一个 texel,是纯 gather)。现在不值。

## 代价

- 顶点缓冲固定 183×183。要做成可调分辨率就得重建 mesh,现在没有设置面板,先钉成
  常数;真机发热读数出来后可能整体下调,那是改一个常数的事。
- 几何仍提交两遍(场景 + 遮挡层),现在是 13.4 万顶点 × 2。要省的话仍走
  `crates/render3d/README.md` 里记的那两条路(卡片隐藏时关掉遮挡相机,或改全屏 pass)。
- 透明度分平台:桌面 `AlphaMode::Blend` 画软边发光圆点,安卓 `AlphaMode::Mask` 画硬边。
  同一效果两种观感,理由是小米13(Adreno)上半透明小元素整片不显示 —— 本仓踩过,
  见 `crates/render3d/README.md`。
