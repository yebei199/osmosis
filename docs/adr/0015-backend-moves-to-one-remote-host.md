# 后端整体搬到一台远端主机,所有设备连它

日期:2026-08-01。状态:已采纳。

## 背景

歌单、播放历史、听歌统计要在多台设备之间同步。同步的前提是存在一个所有设备都能
连到的、持有唯一真相的远端 —— 「各设备本地各存一份再互相合并」是另一条路,
但那是分布式一致性问题,个人应用不该自找。

此前的拓扑是同机:axum 跑在每台设备旁边,不面向网络、没有鉴权(见 `docs/adr/0009`)。
这个拓扑下「同步」无从谈起。

## 决策

- axum、bang-dream、Postgres 三者部署在**同一台远端主机**上,所有设备(桌面、
  安卓、wasm)连这台 axum。
- axum 与 bang-dream 之间仍是同机回环 —— bang-dream「调用方只有同机 axum、
  不面向公网」的边界**不变**,变的只是这对组合从每台设备旁边搬到了远端。
- Postgres 归 axum 独占。bang-dream 保持零业务落盘(它只落登录凭据与设备指纹)。
- 客户端本地**不建库**:列表数据内存缓存,封面落磁盘目录。SQLite 镜像留给
  离线音频那一期 —— 断网可用是那时才真正出现的需求,现在建表就是白养 schema。

## 备选方案

**每台设备本地 axum + 独立同步服务。** 不选:两套服务、两套契约,且网易云凭据
在每台设备上各登各的,「换设备不同步」的问题只解决一半。

**客户端直连远端 Postgres。** 不选:数据库端口暴露给客户端等于放弃所有校验边界,
且 wasm 端根本连不了。

## 代价

- axum 面向网络了,不能再裸奔 —— 鉴权由 `docs/adr/0017` 的账号体系补上。
- 冷启动依赖网络。断网时应用只能播已在内存里的东西,列表浏览不可用,
  直到离线那一期补上本地镜像。
- 部署从「本机跑起来就行」变成真运维:远端主机、进程管理、Postgres 备份。
