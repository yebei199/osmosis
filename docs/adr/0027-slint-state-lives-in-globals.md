# Slint 状态面住在 global 单例里,不由 MainWindow 转发

日期:2026-08-14。状态:已采纳,随 `app.slint` 拆分落地。

## 背景

`crates/ui/slint/app.slint` 有 2004 行,其中 431 行是 `MainWindow` 的属性与
回调声明——200 多个,是 Rust 侧 20 个 `bind_*` 函数的唯一 API 面,全部通过
`ui.set_xxx()` / `ui.on_xxx()` 访问。剩下 1504 行是一棵视图树,里面有几个
明显可以外提的整块:播放页 417 行、音乐页 706 行、Home 页 148 行。

组件外提的模式仓库里已经有了,`app.slint` 已经 import 了 14 个 `.slint`。
但那些外提的都是无状态控件。这次要外提的是整页,而页面要读写那 200 多个属性。

## 决策

**属性面按域拆成 `export global` 单例**:`Player`(播放与传输)、`Viz`(可视化与
播放页几何)、`Library`(歌单/搜索/红心)、`Session`(登录与个人页)、`Shell`
(版式、tab、卡墙、同播、GPU 纹理槽)、`Nav`(导航条目表,已存在)。

子组件直接读写 global,**不做属性转发**。Rust 侧 `bind_*` 改用
`ui.global::<Player>().set_xxx()` 访问。

**纯视觉的派生几何不进 global**,跟着它的组件走。global 只放 Rust ↔ UI 的
状态契约。导航选中器那批带 `animate` 的派生 length 是分界线上的例子:其中
`nav-bg` 由 Rust 侧渲染读取,留在 `Shell`;其余跟着 `navshell.slint` 走。

## 备选方案

**属性留在 `MainWindow`,子组件用 `<=>` 双向绑定拿到**。不选。它的好处很实在:
Rust 侧零改动,纯机械搬迁,可以逐块提交。但它治标不治本——`MainWindow` 依旧是
200+ 属性的上帝对象,每个子组件头部挂一段转发样板,以后每加一个属性要动
`root` 和转发链两处。行数挪走了,耦合原封不动。而且改 `bind_*` 调用点的成本
本来就要付:这次拆分反正要逐个搬 `bind_*` 函数,顺手把访问方式换掉是同一次
触碰,不是额外一轮。

**只拆属性面成组、视图树不动**。不选:属性成组后 `app.slint` 仍有 1500 行视图树,
硬线照样过不去,等于把工作做了一半还得再来一次。

## 代价

- 这是整个拆分计划里改动面最大的一步,`crates/ui` 全部 `bind_*` 都要改访问方式。
  分两次提交(先 global 再拆页面),中间那次 UI 行为应完全一致,是天然的回归检查点。
- `compact` 由 `changed` 回调命令式赋值以剪断布局求值环。移进子组件时若改成
  `in property` 再回传,环会重新出现,必须保持命令式赋值这一侧。
- `renaming` / `confirming-delete` 存的是歌单 id 而非布尔,为的是让状态随歌单
  切换自动作废。进 global 时不能顺手简化成布尔。
- **验证只能靠真机**:桌面窗口比手机扁、safe-area inset 恒 0,贴边几何的问题
  桌面看不见。这一步收尾必须在 Android 真机上复核播放页与音乐页。
