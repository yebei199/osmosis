# 模块按同名目录拆分,不用 mod.rs

日期:2026-08-14。状态:已采纳,随超长文件拆分逐个落地。

## 背景

全仓 23 个文件超过或逼近 `CLAUDE.md` 的 700 行硬线,最长的
`crates/ui/src/music.rs` 有 2421 行。在此之前每个 crate 的 `src/` 都是一层
平铺文件,仓库里零个 `mod.rs`,也零个 `src/` 子目录——不是有意的决定,只是
还没有文件长到需要下一层。

现在要下这一层,得先定它长什么样。

## 决策

- **同名目录**:`foo.rs` 是模块根,子模块落在同级的 `foo/` 目录里,由
  `foo.rs` 用 `mod bar;` 声明。模块根负责把子模块的对外符号 `pub use` 回来,
  **crate 外部的调用路径一律不变**。
- **不使用 `mod.rs`**,任何位置都不用,包括 `tests/` 目录下的集成测试。
  集成测试需要跨文件共享夹具时,让 `tests/foo.rs` 保持单一测试二进制,
  子模块落在 `tests/foo/` 下,夹具留在根由子模块 `use super::*` 取用。
- **测试留在单元测试里**,搬进 `foo/tests.rs`,不外移到 `tests/` 集成目录。
  测试自身超过 400 行时,`foo/tests.rs` 继续按主题声明 `mod`。
- **尺寸**:按内聚切,软上限 400 行、硬上限 700 行。宁可让一个强连通的
  `impl` 块留在 500 行,也不为凑行数把它拦腰斩断。

## 备选方案

**`foo/mod.rs` 加平级子文件**。不选:`mod.rs` 是 2015 edition 的遗留写法,
一个项目里开十几个都叫 `mod.rs` 的文件,编辑器标签页和搜索结果全是重名,
定位靠目录名而不是文件名。2018 edition 起同名目录是官方推荐。

**平铺文件加前缀**,如 `music_rules.rs`、`music_list.rs`。不选:目录本来就是
语言给的分组手段,用文件名前缀模拟它,是把层级信息编码进字符串;而且
`music.rs` 里的 `cloud::Spin` 这类路径会被迫改成 `cloud_spin::Spin`,
调用点跟着一起改,拆分从「搬文件」变成「改引用」。

**单元测试外移到 `tests/` 集成目录**。不选:外移会丢掉私有符号访问,得为此把
`full_cause`、`clamped_volume`、`decode` 一类内部函数放宽成 `pub(crate)`。
拿架构换行数,方向是反的。

**`tests/common/mod.rs` 共享集成测试夹具**。这是 Cargo 的惯用法(`tests/common.rs`
会被当成独立测试 crate 编译),但它要求 `mod.rs`。改用「单一测试二进制 + 子目录」
后夹具照样共享,而且不会让同一批测试分裂成多个二进制去抢数据库连接。

## 代价

- 模块根多出一段 `pub use` 样板,拆完要逐个核对公共面。`crates/api` 有约 40 个
  请求函数是 crate 公共 API,漏一个 `crates/ui` 就编译不过。
- `crates/ui` 与 `crates/api` 里带 `#[cfg(target_arch = "wasm32")]` 的模块,
  拆分后每个新 `mod` 声明都要带对应 cfg,漏了 wasm 构建才炸,桌面测试看不出来。
- 共享私有状态(`music.rs` 的 `Deck`、`server/src/main.rs` 的 `AppState`)要从
  私有放宽到 `pub(crate)` 才能被子模块访问。这是本决策唯一承认的可见性妥协,
  范围限在模块树内,不外溢到 crate 公共面。
