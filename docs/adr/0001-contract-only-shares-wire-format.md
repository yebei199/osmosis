# 客户端与服务端只共享线上格式,不共享领域模型

服务端与客户端同处一个 workspace,共享一个 `contract` crate。这个 crate 里只有请求体、
响应体、错误码和协议版本号,**没有任何领域规则**。两侧各自维护自己的领域模型
(`crates/app-core` 与 `server/`),二者只在 `contract` 处相遇。

## 为什么

诱惑在于共享领域模型:"取消订单不能取消两次"这条规则两边都要用,写两遍会漂移。
但共享领域模型会把两个截然不同的约束绑在一起 ——

- `app-core` 必须能编到 `wasm32-unknown-unknown`:不能碰文件系统、不能开线程、
  不能依赖 tokio。
- `server` 需要事务、连接池、DB 映射。

一旦服务端往共享的领域 crate 里加了一个 `sqlx::FromRow`,web 端就编不过了。
而这个约束**不会在服务端的 CI 里暴露**,只会在某个人下次构建 wasm 时才炸,
且他还得回过头去理解为什么一个领域规则里有数据库代码。

代价是接受了一定的重复:两侧的校验逻辑可能各写一遍。这是自觉支付的成本。

## 强制约束

`crates/contract` 的依赖只允许 `serde`(以及 `serde` 生态里同样 no-IO 的 crate)。
**永远不许出现 `tokio`、`sqlx`、`reqwest`、`axum`。**
这条约束应当由 CI 检查,而不是靠记忆。
