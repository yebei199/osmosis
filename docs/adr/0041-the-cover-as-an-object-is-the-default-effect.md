# 封面实物是播放页的默认效果,标注卡与遮挡层退役

日期:2026-11-12。状态:已采纳(用户同日确认效果入口留在播放页右上角,不进抽屉);
2026-11-13 修订:第一节「随音乐动的只有光」被第五节取代,新增第六节「点云铺满视口」。取代 [`0014`](0014-one-visual-preset-with-the-seam-left-in-place.md);
修订 [`0010`](0010-play-page-decoration-in-3d-function-in-2d.md) 的「粒子从卡片前后穿过」与
「深度卡片现在是标注卡」两节、[`0012`](0012-cover-point-cloud-is-one-mesh-in-the-bevy-scene.md)
的「自动同时进两台相机、白拿遮挡设施」。

## 背景

播放页的 3D 主体是封面点云:九千多颗方块砌成的封面随声音起伏。用户判它当默认不好看 ——
那是一层「效果」,不是这首歌的封面本身。

同一页上还有三样只为一个演示存在的东西:一枚绕轨道慢转的白色方块、挂在它前表面上的
世界空间标注卡、以及为了让粒子逐像素挡住那张卡而开的第二台相机(遮挡层)。卡片的内容是
曲名,下方的歌名行就写着同一句话;遮挡层每帧把整个场景再提交一遍(真机量过 +22%)。
它们证明了「深度正确的 UI」做得出来,但在播放页上没有产品意义。

另有一处版式缺陷:宽版式为了给右边那栏字腾地方,`.slint` 把整张场景图往左推了两成窗宽,
而图本身只有一个窗宽 —— 右边那 20% 没有任何 3D 内容,出界的东西在那条边上被硬切。

## 决策

**一、默认效果是「封面实物」**(`crates/render3d/src/sleeve*`)。封面印在一块薄封套上
(圆角、半圆倒角、厚度 3.4%),一盏写死在着色器里的柔光从左上照着,正面一道很淡的光泽随
偏转滑过;下面一片暗色亮面地板,地板里是封套淡出的倒影与一道接触阴影。

- 倒影是一份**镜像网格**,不是第二台相机、也不是屏幕空间反射。镜像烘进几何(y 取反、绕序反转),
  实体的变换因此仍是正常旋转,背面剔除照开。地板与倒影半透明:桌面 `Blend`,安卓 `Mask`
  加 4×4 有序抖动 —— Adreno 上 Blend 整片不显示的坑([`0012`](0012-cover-point-cloud-is-one-mesh-in-the-bevy-scene.md)、
  `crates/render3d/README.md`)还在。
- ~~**随音乐动的只有光**~~(已被第五节取代):平滑过的低频推亮倒角那一圈边缘光。几何不跟鼓点
  抖 —— 那是点云的语言,一张实物封套跟着节拍晃,看着像坏了。
- 运动只有三种:很慢的呼吸(约 ±3° / ±2°,11s 与 15s 两个周期);拖动偏转(橡皮筋,上限约
  40° / 25°)、松手由欠阻尼弹簧拉回原位;换歌时旧封套加速甩向左后方并翻开,新封套从它后面
  落位、冲过头一点再停,0.8s。两张始终不互相穿过,不靠透明度遮丑。
- 先换歌、封面后到(绝大多数情形):旧封面甩走,落位的是一张空封套,封面到了在上面显影;
  不甩第二次。「不留着上一首」与点云同一条规矩。

**二、「效果」是顶层选择,点云降为可选的第二个。** 编号 seam 从「点云的子预设」改为「效果」:
`Viz.viz-effect`(0 封面实物、1 点云)→ `VizControls::effect` → `VizFrame::effect` →
`render3d::effect::Effect`。两摊实体常驻,只有当前那一摊可见,另一摊 `Visibility::Hidden`,
一帧不画;两摊都收封面,切过去不重建、不等图。点云的 `preset` uniform 与 `preset_index`
一并删除 —— 只剩一档的子预设没有存在的理由(这正是 0014 留着那条 seam 等的「加第二档」,
只是第二档长在了上一层)。

- 入口在播放页右上角:一枚与左上角队列入口对称的药丸写着当前效果名,点开是一列带字的行,
  当前那行强调绿加勾([`0023`](0023-green-is-the-only-accent.md))。0014/0029 说过「加档时回到抽屉里」,
  这里不照做:选的是这一页自己的样子,只在这一页看得见;放进全应用共用的抽屉,在别的页面上
  就是一行点了看不出变化的设置。它也不违反 `docs/design.md` 硬规则 4 —— 那条管的是音乐功能
  (播、停、切、进度),效果是装饰的外观,换不换都不影响任何功能。
- 选择跟着设备落盘:`api::settings` 加 `viz_effect`,写名字(`object` / `cloud`)不写编号,
  认不得的名字只把这一项落回默认,不连带冲掉音量。

**三、删除标注方块、标注卡与遮挡层。** `marker.rs`、`viz-anchor-*`、`viz-occluder`、
`spawn_occluder_camera` / `occluder_depth` / `anchor_viewport`、`VizFrame::needs_occluder`、
`VizImages` 全部删除;`render_viz_frame` 只交回一张场景图。播放页的合成从五层变成三层:
糊封面背景 → 3D 场景 → 字与控制簇。

0010 的边界随之收窄:**「装饰入 3D、粒子可以从卡片前后穿过」那一档退役**。播放页上不再有
参与深度合成的 2D 元素;「装饰在 3D、功能在 2D」与「被遮挡的东西必须在别处有等价路径」两条
照旧有效。深度正确的 UI 这条路线没有被否定 —— 它的做法与代价记在 0010、0012 与
`docs/blog/depth-correct-slint-ui-over-bevy.md`,哪天有一个真正需要被场景挡住的对象,
从 git 里取回来。

**四、主体的「偏左 / 偏上」由相机移轴做,场景图铺满整窗。** `.slint` 不再平移那张图;
`VizFrame::compact` 把版式带进 render3d,`camera::lens` 用 bevy 的 `SubCameraView` 把主轴放在窗宽
0.3(宽版式)或窗高 0.36(紧凑版式)处。移轴与「把居中渲好的图整张平移」逐像素相同,点云的
观感一点不变;区别是平移出去的那一边也有内容。纵向移轴时 bevy 把视野对齐到整幅画面的高,
视野按同一倍数放大才不缩放(单测钉着)。bevy 的视锥剔除仍按不移轴的那一幅算,两个效果的
实体都挂 `NoFrustumCulling`。

**五、封面实物跟着节奏动 —— 跟事件,不跟电平**(2026-11-13,用户:「实物封面还是需要随着
歌曲节奏有运动」)。第一节的判断只对了一半:逐帧跟着电平走的几何确实像坏了,但一张对鼓点
毫无反应的封套在音乐里是死的。分界不在「几何动不动」,而在「跟的是连续的电平还是离散的事件」。
三样各管一段频率(`crates/render3d/src/sleeve/beat.rs`,纯状态机,有单测):

- **低频起音 → 往前顶一下。** 起音 = 电平高过它自己最近的滑动平均(时间常数 0.4s)1.4 倍以上、
  且至少高 0.06、本身不低于 0.12;不应期 0.12s,并且边沿触发 —— 触发后要先落回门槛下才重新上膛,
  持续的低音与缓慢爬坡都不会连发。强度 = 高出量 / 0.3,封顶 1。每次起音给一份冲量,封套峰值放大
  2.5%(在相机距离上就是往镜头靠近 2.5%)并点头约 1.3°(顶边朝人);弹簧临界阻尼、ω = 26,峰值在
  约 38ms,200ms 时只剩 8%,**不往后缩** —— 欠阻尼的话一下鼓就成了「咚 —— 嗒」,鼓点密了就是抖。
  弹簧按闭式解推进,不数值积分:这么硬的弹簧,半隐式欧拉在 120Hz 步长上会吃掉两三成峰值,
  而且随帧率变。叠起来的推量封顶 1.4 倍。用缩放而不用平移:平移量换算到画面要乘台面缩放,
  同一下鼓在手机和桌面上就不一样大。
- **中频响度 → 呼吸摆幅。** 中频平滑(起 0.8s、落 2.5s)后在 0.10..0.45 之间把呼吸的摆幅从 1 倍
  放到最多 2.2 倍(左右约 ±6.6°、前后约 ±4.4°)。只改幅度不改相位,响度又是按段落平滑的,
  所以是慢慢涨落,不会跟着某一个字抖。安静的段落就是原来的呼吸。
- **高频起音 → 光泽闪一下。** 另一路起音检测(平均 0.25s、1.5 倍、至少高 0.04、下限 0.05、
  不应期 0.08s),只进着色器:正面那道光泽亮起来、整面铺一层很薄的光,0.1s 衰减。不碰几何。

与已有运动的组合:鼓点与摆幅叠在呼吸与拖动之上(拖动时照样跟拍子);换歌交接那 0.8s 不起新鼓点
(正在落位的封套再被顶一下,两个运动搅在一起就乱了),检测照常喂、平均一直跟着;退场那张不跟拍子。
封套不在显示时全部清零,检测器切回来先用第一帧立平均 —— 拿藏起来之前的平均去比,第一帧就是
一次假鼓点。低频电平推亮边缘光那一条保留。

**六、点云铺满视口**(2026-11-13)。点云是一块固定 4.8 见方的平面,在 z = 1.8 处正对 z = 8 的相机,
宽版式又靠第四节的移轴把主轴放到窗宽 0.3 处 —— 16:9 下视口在点云平面上横跨 −2.74..6.39,
封面右边缘 2.4 只到视口宽的 56% 左右,右边四成多是一整条没有任何方块的背景。第四节把「图本身
只有一个窗宽」修好了,但点云自己就没有那么宽。

- 封面那 96×96 格**原封不动**:同一份格点、同一条 uv 式子、同一个逐颗随机数,顺序也一样(单测钉着)。
  外面按同一格距(`CELL_WORLD`)接着往四边铺,方块大小与形状不变 —— 场大了是方块多了,不是被拉宽。
- 补多少格由视口在点云平面上框住的那一块定(`cloud/field.rs`):框的高恒为 2·d·tan(视野/2)
  (移轴只平移不缩放),宽乘长宽比,主轴在框里的位置取 `camera::shifts`,与镜头共用一份;单测把
  框的四角投回镜头,正好落在视口四角。再留两份余量:方块往后退 0.25 也还铺得满(远离主轴的方块
  一退,透视会把它往里拉),外加两格。每边封顶 256 格。紧凑竖屏的封面本来就撑出左右与上边,只往下补。
- 外圈的样子:着色器从 uv 越出 0..1 认出外圈,不加顶点属性。颜色取封面**边缘外延**(uv 夹回边上)
  的**高级 mip**(8×8 那一档,越往外再糊一级)—— 一块方块是封面边上一大片的平均,而不是拉丝;
  亮度紧贴封面处压到 0.5,往视口边沉到 0.12(淡出距离按该侧封面边到视口边的距离归一,下限约 24 格,
  上下只多出三四格的那两条边不至于一出封面就黑);起伏从封面边起约 14 格内平滑降到 0.35 倍。
  封面边上那一步亮度落差是有意的:满屏是方块,主体仍是中间那张清楚的封面 —— 这正是从前「放大到
  12 铺满四边之后只像一层网点」那次失败缺的东西。
- mip 在上传封面时由 CPU 逐级 2×2 平均生成(`scene/mips.rs`),整条链随原图一起传;封面长边不过 512,
  多算三分之一的像素。bevy 不替上传的图生成 mip,为一首歌一次的事起一条 GPU blit pass 不值。
  第 0 级照旧是原图,封面那块与封面实物都仍按第 0 级取,观感不变。
- 换歌过渡照旧作用于外圈:脉冲外扩、curl 流场都按格算;错峰相位的「到中心距离」在封面里仍是 0..1,
  外圈接着往外涨、封顶 1.7,外圈比封面的角更晚落。平帧上外圈不采「上一首」那张。
- 重烘时机:视口要的场变了、并且稳住 0.2s(墙上时间,播放页时钟在门关着时不走)才重烘一次;
  已建的比要的多出 8 格以内不缩。只换实体上的 `Mesh3d`,材质、两张封面与过渡不动。拖着窗口边
  改大小时途中不重烘,停手后一次。只在点云露面时看;藏着时视口怎么变都不花这份工,切过来补上
  (那一刻视口若已变过,会有 0.2s 露边)。
- 代价是方块数随长宽比涨:16:9 宽版式 194×112 = 21 728 颗(原 9216 的 2.36 倍,顶点缓冲约
  25MB、索引约 3MB),16:10 平板横屏 175×112 = 19 600 颗,9:20 紧凑竖屏 96×119 = 11 424 颗。
  比「一倍半到两倍」的预估多,因为宽版式主轴在 0.3 处,右边要补的是左边的八倍。每颗仍是 24 个
  顶点、四个属性,没为外圈多背一份数据。

## 备选方案

**把点云调好看,不加新效果。** 不选:问题不在参数,在形态 —— 九千个方块是一层「效果」,
用户要的默认是「这首歌的封面」本身。点云留着,给想要它的人选。

**封面实物用 bevy 的 PBR(`StandardMaterial` + 灯 + 阴影 + 屏幕空间反射)。** 不选:要开阴影
贴图、prepass 与一整套光照绑定,地板反射还得另起一台镜像相机或 SSR,安卓上又是一摊没验证过的
管线;这里要的只是「一盏灯照着的纸板」和一道淡倒影,一份几十行的片元着色器加一份镜像网格就够。

**宽版式把主体在世界里往左挪,不移轴。** 不选:点云会被斜着看(离开光轴),观感变了;
封面实物露出一侧的厚度,与右侧那栏字的视线方向不一致。移轴让两者都与从前逐像素一致。

**留着标注卡,换一个更有意义的被标注物。** 不选:播放页上没有需要被场景挡住的信息,
每帧 +22% 的第二遍绘制换不来任何东西。

**封面实物的鼓点用欠阻尼弹簧或逐帧跟低频电平。** 不选:前者每下鼓多一下回缩,后者就是第一节
否掉的持续抖动。离散的起音加临界阻尼,事件之间封套是静的。

**点云铺满视口改用放大平面(PLANE_SIZE 跟着长宽比涨)。** 不选:那会把封面本身也放大、格子变粗,
点云在原来那块地方就不一样了;也是「放大到 12」那次失败的老路。

**外圈的糊色用片元里多点采样原图,或另传一张缩略图。** 不选:顶点着色器每颗 24 个顶点都要采,
五六个采样乘两张图在外圈上是十几万次采样一帧,而且几个点采样凑不出「糊」,只是几张重影;
另传缩略图要两个新绑定和一条换歌时的轮换。mip 是同一张纹理多几级,一次采样就是一片平均。

## 代价

- 两个效果的管线都按「第一次可见」才编译:第一次切到点云时有几帧空白。没做预热 —— 切换是
  低频操作,不值得给它也排一条卡墙那样的预热。
- 封套仍按第 0 级取封面:在小屏上缩到三四百像素时,高频的封面细节会有一点闪。mip 链自
  第六节起已经随封面上传了,要压只差着色器按屏幕导数选级(它在 `discard` 之后,得手算)。
- 安卓上的倒影与地板是抖动出来的,近看有网点;远看与桌面的混合一致。
- 编号在 `.slint` 的 `viz-effect-names`、`ui::viz::effect` 与 `render3d::effect` 三处手工对齐。
