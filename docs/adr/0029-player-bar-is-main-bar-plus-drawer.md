# 播放控制条回到主条加抽屉,三面轮换废除

日期:2026-08-16。状态:已采纳,取代 `0028` 的三面轮换部分。

## 背景

`0028` 把控制条的功能分成三面轮换,那个结构有两条命:一条是给 3D 三棱柱当面,
一条是手机宽度一排放不下。棱柱那条路做到 GPU 凸体射线求交(真剪影、真受光、
可见端面)仍被判定不成立并整体撤回(621bfc6,#83 以 not planned 关闭):条身宽
是高的九倍,静止时任何渲染方式都接近正对相机、看上去就是平的;而只转「底」不转
键,人眼只会读作换壁纸。

棱柱死后,三面轮换只剩代价:每面内容不一样多,宽度就不一样(410/580 → 210/250 →
250/270),翻一次面条就变一次长 —— 用户点名的「长度不统一」正是它;低频功能翻两
下才够得着;三颗指示点还是必需路径(TouchArea 不转发,按在键上拖不动)。

同时用户点名了另外两条:三处实例像素级不一致(迷你形态少上一曲、少时间,环
40px 对 48px 对 68px);随机/循环开没开根本看不出 —— 深色档下 `accent` 与
`accent-ink` 是同一个 #8fc46a,开关两态的唯一差别是图标暗 15%。

## 决策

**一根条,一种形态,四处实例(首页、个人主页、设置、音乐页、播放页覆层)完全
一致**,只有可用宽度随页面不同,窄了曲名先让位、省略号收尾。迷你播放条这个
形态废除,词条从 CONTEXT.md 移除。

**主条只放高频核心**:封面 · 曲名/歌手/时间 · 上一曲/环形播放键/下一曲 ·
抽屉键 · 下缘进度轨(触屏钉住不隐,`0028` 这条保留)。封面兼任播放页的进出口:
条外点它展开,播放页里点它收起 —— 不再有专用的 ▲/▼ 键,竖向进度条随之删除
(条上的横轨是唯一的 seek 面)。

**其余全部住进向上展开的抽屉**:随机、循环、音量滑块常驻、同播设备区。抽屉也是
到处同一层 —— 行数与高度不随页面变,否则「展开」在两处就不是同一件事(初版让
播放页多一行视觉预设,当场被指出来)。每行带文字标签 —— 循环的三态直接写
「循环:列表」,不再靠图标微差。点条外任意处收起。未来的筛选与均衡器直接加行,
主条永不膨胀。

**收起用的那块全屏 TouchArea 声明在最前面**。slint 的层序即声明序,命中测试也
从上往下走;排在后面就压住整根条,每一次点击都被吃成「收起抽屉」。这个 bug
骗得过一整组按无障碍标签点的测试 —— 那条路不过命中测试 —— 所以抽屉的可点性
由派发真指针事件的测试盯着。

**开关状态用填充表达**:开着的开关整颗填强调色、图标反白;关着的透底描边。
不再用「同一颗键两种亮度」—— 那在深色档下是不可分辨的(token 重合是诱因,
但即使 token 分开,亮度差也是最弱的一类区分)。

**环形播放键的彩虹圈改为常驻**:warp 那条 pass 不再只在播放页打开时跑(可以只
渲环那么大一块),桌面与安卓的每一处环都是同一圈随音乐翻涌的彩虹。web 与 iOS
没有 render3d 管线,环退回纯色 —— 平台内完全统一,跨平台的这条差异被明知并接受
(渐进增强的既有约定,`0011`)。

## 备选方案

**保留三面、强制等宽**。不选:等宽是当初为刚性棱柱付的价,棱柱死了,留白只是
留白;翻面的发现性成本与指示点的必需性一样没解决。

**抽屉里也用图标网格**。不选:抽屉里有的是横向空间,写字的成本为零,而循环三态
靠图标猜正是这次被点名的毛病。

**非音乐页保留缩小版条**。不选:主条紧凑档已能放进 360px,「缩小版」在技术上
不再必要,而它正是三处不一致的最大来源。

## 后果

- `0028` 的三面结构、`Shell.bar-face`、三颗指示点、翻面手势与 `music/prism.rs`
  的落点计算全部退场;`0028` 保留下来的只有「一个组件四处实例」「进度轨常驻」
  「补间与状态真相在 Rust」这几条。
- 播放页覆层的 `VerticalSeekBar` 与两颗专属键(视觉预设、收起)退场:收起归封面;
  视觉预设连同它那张选择列表一起删除 —— 名册只剩「封面」一档,一个选不动的选择器
  却让播放页的抽屉比别处多一行。加回第二档时入口进抽屉(`slint/drawer.slint`)。
  `0010` 的「功能永远在最上层 2D」不受影响。
- 时间读数全应用只剩一份(主条上),播放页右缘那份删除。
- 主条紧凑档固定开销约 226px,360px 手机上曲名约有 100px —— 此前音乐页只剩
  36px。
- 三处水平内缩(此前 16/24/32px)统一成一个值。
