# 播放控制条收成一个组件,分三面轮换

日期:2026-08-16。状态:**部分被 `0029` 取代** —— 三面轮换废除(棱柱死后它只剩
代价:翻面变宽、低频功能藏两层、指示点成了必需品)。仍然有效的是:一个组件多处
实例、进度轨常驻、补间与状态真相在 Rust。

## 背景

播放控制条在四个地方各写了一遍:`musicpage.slint` 里宽版与紧凑版两段内联条身、
`playpage.slint` 里覆层控制簇、`controls.slint` 里的 `MiniPlayer`。玻璃胶囊那套
样式(`surface.with-alpha(0.9)` + `glass-edge` + 30px 投影)因此复制了四份,展开
播放页那颗键复制了两份,而个人主页与设置页干脆没有条 —— 换到那两页就没有任何
控制入口。

同时条上的功能还在长。已经在的是封面、曲名、时间、上下曲、播放、随机、循环、
音量、同播;计划中的还有粒子云设置、筛选与音乐平衡。宽版一排的最小宽度已经约
470px,而手机内容区只有 ~360px —— 那正是紧凑版当初拆两行的原因。再往一排里加
东西,两种版式都要重排,而且每加一次都要重排一次。

## 决策

**一个 `PlayerBar` 组件(`crates/ui/slint/playerbar.slint`),四处只剩四个实例。**
迷你与完整、宽与窄、页内与覆层的差别全部收进组件内部,调用点只给位置和宽度上限。

**功能分三面轮换,不再一排平铺。** 面 A 播放核心(封面、曲名、时间、上下曲、
环形播放键、播放页出入口),面 B 模式与声音(随机、循环、音量),面 C 同播与特效
(同播设备、视觉预设)。翻面靠条右缘那三颗指示点,以及之后的上下滑手势。
加新功能是给某一面添一颗键,不是把整条挤窄一格。

**三面共用一个全局面号** `Shell.bar-face`,不是每个实例各存一份。音乐页的条与
播放页覆层的条是同一条的两个实例,翻了一个另一个也该跟着 —— 那本来就是同一件事
(状态住 global 的理由同 `mem:` 0027)。

**每面各有各的宽度,写死在组件里。** 不让条收内容宽:三面的内容各自长在 `if` 里,
而条件子元素不给父元素贡献 preferred 尺寸,收出来是 0。三面共用一个钉死的宽度也
不行 —— 只有两三颗键的模式面与同播面会摊在一大片空胶囊里(实拍确认过)。

**进度轨跨三面常驻。** 翻到模式面、同播面时,拖动落点的能力不跟着翻走。这是
`0010` 的「功能永远有等价路径」在翻面结构上的落点:翻面可以藏起一簇**键**,
不能藏起**能力**。紧凑版式里这条轨钉住不隐 —— 触屏没有悬停,要指过来才现形的
轨道在手机上等于不存在。

## 与 0010 的关系

条身背景之后会由一条 wgpu pass 画成真透视的三棱柱(#83),但**按键仍是 Slint
的 2D 元素**,画在那张图之上,命中测试照旧走 Slint。这不触碰 `0010`:3D 只做
装饰,功能留在最上层 2D、永远点得到。

反过来说,如果哪天要让按键贴在柱面上跟着转,那就是把「只能在 3D 里完成的操作」
加了进来,按 `0010` 自己的条款必须先回去改那份决策,而不是在这里绕过去。

## 备选方案

**一排平铺,只重排顺序与间距。** 不选。它最省事,但没有解决「功能还在长」这件事:
下一个功能进来时,宽窄两种版式还是各挤一次,而手机那一排早就顶到上限了。

**主条 + 向上展开的抽屉。** 一度是首选,也仍然是三面之外的溢出去处,但单靠它不够:
抽屉是「不常用的收起来」,而随机、循环、音量、同播都不是不常用,把它们塞进抽屉等于
每次都要多点一下。三面轮换是平级的分组,抽屉是层级的收纳,两者解决的不是一个问题。
本次只留接缝,不建抽屉 UI —— 第一个真正的住户(筛选或均衡器)到位时再建。

**迷你条与完整条各自成组件。** 不选:两者的差别只是摆哪几件,而它们要共用同一套
胶囊样式、同一颗环形键、同一组回调。拆成两个组件,那套样式就又有了两份,而这次
改动的起点正是它有四份。

## 影响

- `ControlCluster` 与 `MiniPlayer` 退场,`controls.slint` 只剩两块跨形态复用的
  积木:`RingControl` 与 `SyncStrip`。
- 紧凑版式不再拆两行:三面各摆一簇之后,宽窄都是单行,`viz-controls-h` 的两档
  合成一档。
- `ProgressBar` 多一个 `pinned`:细轨在触屏上钉住不隐。
- 条身尺寸仍按原样回写给 GPU 背景通道,页内那条走 `bar-w/h`、覆层那条走
  `viz-bar-w/h`。两槽不合并 —— 播放页盖着音乐页时两条同时在场,共用一槽会互相
  踩掉对方的尺寸。
- 翻面的补间动画不在这一层:摆在布局里的元素,`width` 归布局管,组件自己
  `animate` 不上(slint 直接拒编)。补间连同棱柱转角一起在 #83 做。
- **指示点是必需路径,上下滑只是快捷方式**(#82 实测):slint 的 `TouchArea`
  不转发事件,按在按钮上起手的拖动归按钮,翻不了面。模式面中段几乎全是键,
  那里基本拖不动;条身与文字上起手则正常。三颗指示点在任何一面上都点得到,
  是唯一在每一面都成立的那条路。落点算术在 `ui/src/music/prism.rs`,不在
  `.slint` —— 无头测试驱动不了真实指针,留在界面里就没有测试盖得住。
