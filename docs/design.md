# UI 设计

界面的设计原则、结构现状,以及改界面前必须过一遍的硬规则。术语的定义在
[`CONTEXT.md`](../CONTEXT.md),每条决策的来龙去脉在 [`adr/`](adr/),这里只讲
它们合起来构成的那个设计。

当前设计来自 2026-08 的整体改版(Claude Design handoff,规格全文在
[`design/handoff-readme.md`](design/handoff-readme.md)。设计源稿在 Claude Design:
<https://claude.ai/design/p/457861b1-7d61-4b09-88bd-3803fd9c0027>(`osmosis-aurora.dc.html`
为按钮五变体,`osmosis-inplace.dc.html` 为第六轮「按钮落位 · 水滴导航」,6a-6e
已全部实施,见 #67 及其四个子任务)。shader 分层拆解在
[`design/handoff-shaders.md`](design/handoff-shaders.md),光带按钮参考实现在
[`design/aurora-button.js`](design/aurora-button.js);原始交付包不在工作树里,
取法见 [`design/handoff-readme.md`](design/handoff-readme.md) 顶部)。本文件与
handoff 冲突时,以本文件为准 —— handoff 是冻结的交付稿,本文件跟着实现走。
改版跟踪 issue #56 与 #67 都已整体交付关闭。

## 原则

**功能与氛围分家。** 操作类功能(播/暂/切/进度)由常驻控制条承载;播放页只管
沉浸与氛围,不新增任何只能在它里面完成的操作([`adr/0010`](adr/0010-play-page-decoration-in-3d-function-in-2d.md))。
装饰层可以遮挡界面元素,但被遮挡的东西必须在别处有等价路径;装饰整层消失时,
应用功能完好无损。

**屏幕说什么,耳朵就听什么。** 点歌先换界面:旧歌立刻停,新歌名与封面立刻上,
播放页挂加载态,声音几秒后进来(见 CONTEXT「队列」)。换歌时封面、歌词、点云
都不留上一首的内容等新内容:旧图配新歌比空着更误导。

**出问题的状态自己开口。** 断流停在原地并给一条跨页横幅,文案先说发生了什么,
探明之后再说是哪一种([`adr/0013`](adr/0013-a-broken-stream-is-a-reportable-ending.md))。
静默失败等于把排查成本转嫁给用户。

**界面上没有摆设。** 瓦片只放真实存在的应用,开关只在背后有数据时出现,
统计只画真数字。视觉可以先于功能落地,谎报状态的控件不可以。

## 壳与导航

Osmosis 是承载多个应用的壳,音乐是第一个应用(见 CONTEXT「壳」「应用」)。

- **Home 属于壳**:画成应用启动器,3D 瓦片场浮在场景里,当前只有 Music
  一张真瓦片加一个「＋装一个」空槽([`adr/0024`](adr/0024-home-is-the-shell-launcher.md))。
- **控制条跨应用常驻**:壳级一个实例,悬浮在底部,有歌就在。
  在任何应用里都能控播放,这是「壳」概念的具体体现。没有缩小形态 ——
  「迷你条」曾是三处不一致的最大来源([`adr/0029`](adr/0029-player-bar-is-main-bar-plus-drawer.md))。
- **宽版式导航**:左侧 76px 图标栏,Home 与 Music 在上,个人与设置沉底(glass 圆钮)。
- **紧凑版式导航**:底部 48px 四项(Home / Music / 搜索 / 我的),控制条
  浮在它之上。
- 播放页不占导航位,从控制条的封面展开、再点封面收起(见 CONTEXT「播放页」)。

## 音乐页:卡墙与列表

音乐页主视图是 3D 卡墙:当前一批曲目的封面卡在深度上散开,拖动旋转、滚轮推拉、
单击浮起、双击播放。列表与卡墙是同一批卡的两种摆法,切换只是深度插值,不换页面
([`adr/0025`](adr/0025-card-wall-is-the-music-main-view.md))。
无 GPU 的构建(web / iOS 默认)退回列表视图。

次级入口(每日推荐 / 我的歌单 / 最近播放 / 红心)走 `MusicRail`。设计稿里它是
标题行右侧的一排胶囊,那一版**定为不做**(理由见
[change_log/2026-08-11/card-wall.md](change_log/2026-08-11/card-wall.md) 的 Known Cuts),
现有 MusicRail 继续服役。

卡墙的列距行距按容器尺寸计算,不写死像素:原稿里两处卡墙用了两套坐标,
跨尺寸复用会错位。

## 版式

两种版式,由视口宽度决定,与端正交:< 600px 逻辑像素为紧凑版式,否则宽版式
([`adr/0007`](adr/0007-layout-mode-by-width-not-by-platform.md))。桌面把窗口
拖窄就能看到移动端的样子,移动端排布因此在桌面上可见、可验证(`just shot 420`)。

紧凑版式的要点:卡墙降到 2 列且相机后撤(`render3d` 的 `pullback`);播放页控制簇
只留上一首 / 环形键 / 下一首;个人主页统计卡 2×2;设置页分组导航折叠成整块卡片流;
触摸目标不低于 44px。播放页那张 220px 封面卡已随封面点云上线删除,点云自己铺满整屏。

## 主题与色板

明暗两套主题,外加「跟随系统」:设置页三选一,存储是三值枚举
(`api::settings`),真相在 Rust 侧(`crates/ui/src/theme.rs`)。跟随系统的
检测当前只有桌面端实现,其余端按深色处理。

颜色全部收在 `theme.slint` 的语义 token 里,具体值以该文件为真相。三族表面不混:

- **常驻界面**(window/base/surface/raised/hover):导航、列表、控制条、卡片,
  跟着明暗走。绿色系:深色底往墨绿走,浅色底往纸绿走。
- **沉浸层**(immersive\*):播放页压在封面与点云上的那块底和字,两套主题下
  取值相同。底钉死,字就得跟着钉死(`crates/ui/tests/theme.rs` 守着)。
- **错误横幅**(danger\*):自成一套,便于单独调。

**绿是唯一的强调色**([`adr/0023`](adr/0023-green-is-the-only-accent.md))。
`accent` 深色下 `#8fc46a`、浅色下 `#4f7a3f`;绿色明度高,压在它上面的
`accent-text` 是深墨而非近白,对比度约 9.4:1。`accent-ink`(中性底上表示选中的
字与图标)仍随主题翻转。

**副色板 12 对**只用于封面占位、卡墙卡片、波形条、统计数字:一屏里颜色可以
很多,「重点」永远只有绿。取用规则 `hues[index % 12]`,渐变从亮色到深色。
真实封面到位后,它们只作为加载前的占位与失败兜底。

## 字体

| 角色 | 字体 | 说明 |
|---|---|---|
| 中文大标题 | 思源宋体 Heavy 子集 | 「每日推荐」这类页面标题与播放页歌名 |
| 拉丁与数字大标题 | Caprasimo | 无中文字形,中文场景一律走思源宋体 |
| 正文与界面 | Figtree | 中文回落到系统字体或 cjk-subset |
| 时长、进度、版本号、标签 | DM Mono | 一切等宽场景;等宽不再是全局观感 |

子集管线在 `just font-subset`;硬编码中文必须落在子集里,
`cargo test -p ui` 的 glyph 测试守着。

## 光带按钮与按钮变体

参考实现在 [`design/aurora-button.js`](design/aurora-button.js)(WebGL,数学与
WGSL 版逐行对应),分层拆解在 [`design/handoff-shaders.md`](design/handoff-shaders.md)
§9/§10。五个变体共用一个片元程序,按 `variant` 分支:

| variant | 用在哪 |
|---|---|
| `ribbon` 光带 | 一次性高光 |
| `nebula` 星云 | Home「＋装一个」空槽,一屏一颗 |
| `fluid` 流体玻璃 | 播放页长条、正在播放胶囊 |
| `glass` 液态玻璃 | 次要按钮,可整屏铺 |
| `progress` 流体进度 | 下载、导入曲库这类有进度的动作 |

铁律三条:**全光谱色相只准出现在 Home 空槽**(别处一律收进绿板,不然它成了
第二个强调色);**必须合批**(所有按钮渲进同一张图集,一个 pass,per-instance
只差 seed 与转速,与 `nav_glass` 同构);**一个总开关**(设置页「动态极光按钮」
关掉即纯色实底,无 GPU 端走同一条关闭分支)。

按钮不再有冻结态:hover 收敛后照样每帧重渲,前台恒满帧那条硬规则(下文第 7 条)
把省电交给平台。`nav_glass` 那侧留的是工作量缓存(位置没变就不重算纹理),
不是会冻住动画的门。

## 水滴导航

选中指示器由三颗球组成(头球/尾球/小水滴),追随系数 0.30/0.19/0.13,同一个
目标位置因系数不同天然拉开先后;Slint 侧粘合用 SDF smooth-min(k≈14px),
不用滤镜链。拆解在 [`design/handoff-shaders.md`](design/handoff-shaders.md) §11,
落在 `render3d` 的 `navglass` pass。宽版式侧栏沿 y 走,手机底栏沿 x 走:同一套
数学,轴对调,系数与三球比例共用(#70)。

轨道的范围两种版式不同:底栏四格全在轨道上;侧栏只有上面两格,沉底的个人与
设置是 glass 圆钮、自己表达选中(#71)。选中圆钮时水滴停在最后一格主项的位置
上并化掉,不然上面还亮着一格、人却在别的页。

## 播放条

**只有一种形态**([`adr/0029`](adr/0029-player-bar-is-main-bar-plus-drawer.md)):
条身是悬浮胶囊(62px 高,所有页面同一套尺寸与内缩),主条只放高频核心:
封面 · 曲名+时间/歌手 · 上一首 · 环形键 · 下一首 · 抽屉键。封面兼任播放页的
进出口。窄容器里让位的是文字列(曲名 > 时间 > 歌手),按键与环永不缩。

环形进度播放键:外圈是 conic 进度环,内圈接 warp 的彩虹画面(无 render3d 的端
退回纯色)。条身下缘常驻一条 4px 细轨管精确拖动 —— 触屏没有悬停,
要指过来才现形的轨道在手机上等于不存在。

其余功能住进**向上展开的抽屉**:随机、循环、音量、同播。到处同一层,行数与
高度不随页面变。开关状态由芯片填充 + 右侧文字表达,不靠图标明暗;
循环三态直接写字(关 / 列表 / 单曲)。点条外任意处收起。

## 播放页与可视化

播放页的装饰在 3D、功能在 2D([`adr/0010`](adr/0010-play-page-decoration-in-3d-function-in-2d.md))。
可视化的主体是封面点云(见 CONTEXT「封面点云」)。功能层就是那根全应用共用的
控制条 —— 同宽、同高、同一层抽屉,封面翻成「收起」。歌名用大标题字体,
歌词与歌名同层画在粒子之上,不参与深度合成。

seek 只有一个面:条上那道细轨(曾经的右缘竖向进度条随 `adr/0029` 退场 ——
同一页两套 seek 面,槽宽、颜色、把手规则各一套)。时间读数也只剩条上那一份。

播放页唯一参与深度合成的是**世界空间标注卡**,它标的是场景里一枚绕轨道慢转的方块:
卡片跟着方块走,方块转到远端时粒子成片从卡片前面过。内容是曲名,在列表与控制条上都有
等价路径,守得住下面第 3 条硬规则。

那枚方块是必要的,不是装饰。锚在封面点云上的版本真机实测卡片一像素都看不见 ——
点云是场景不是对象,三万颗无特征粒子没有「一个东西」可指(`docs/adr/0010`)。

点播放页那两行歌词,歌词页从右侧横向滑出,点云退成背景光,标注卡让位。
景深由透明度与字号按行距递减做出来:Slint 没有高斯模糊,文字要真模糊就得进
3D 走一套字形管线,而那正是卡墙里砍掉内嵌文字的同一笔账。翻译开关只在有译文
数据时出现。歌词可上下拖动浏览,不碰播放进度,松手三秒回到跟随。

逐字歌词不做:`LyricLineDto` 只有行级时刻,平台侧给出字级数据后再评估。

可视化只在「播放页展开 ∧ 正在播放 ∧ 窗口聚焦」时渲染,任一条件不满足即完全
停止:暂停定格在最后一帧,收起与失焦零重绘。

沉浸层不做复古质感:扫描线与噪点已于 2026-08-13 去除(#74),只留一道
vignette 收边,把注意力拢回中心。

视觉预设当前只有「封面」一档,入口与 seam 留着([`adr/0014`](adr/0014-one-visual-preset-with-the-seam-left-in-place.md))。

## 硬规则

都是违反过、或原稿里点名会出问题的,改 UI 前过一遍:

1. 新颜色进 `theme.slint` 的 token,不在别的 `.slint` 里写字面色。例外只有
   图形性绘制(日月开关那幅画)与调试读数。
2. 版式由宽度决定,不由端决定。不写「安卓 = 底部导航」式的分支。
3. 可视化不承载功能,被它遮挡的元素必须在别处有等价路径。
4. 播放页不新增只能在这里完成的操作。
5. UI 依赖 app-core 的方向永久单向,反向禁止(见 CONTEXT「UI 层」)。
6. 绿是唯一的强调色。副色板绝不用于按钮、选中态、链接、状态色。
7. 前台恒满帧,后台暂停(2026-08-11 推翻旧的「静止零重绘」省电门,理由与
   经过见 [change_log/2026-08-11/always-on-rendering.md](change_log/2026-08-11/always-on-rendering.md))。
   渲染循环每帧自请求下一帧;安卓切后台、桌面最小化时平台停发重绘,循环
   自然停摆。桌面失焦不算后台:可见即前台。工作量缓存(导航选中器静止时
   不重算纹理)仍然允许,禁的是会冻住动画的门。
8. 界面上不放假东西:假应用瓦片、无数据的开关、编造的统计都不上屏。
