# UI 设计

界面的设计原则、结构现状,以及改界面前必须过一遍的少数硬规则。术语的定义在
[`CONTEXT.md`](../CONTEXT.md),每条决策的来龙去脉在 [`adr/`](adr/),这里只讲
它们合起来构成的那个设计,不复制正文。

## 原则

**功能与氛围分家。** 操作类功能(播/暂/切/进度)由常驻控制条承载;播放页只管
沉浸与氛围,不新增任何只能在它里面完成的操作([`adr/0010`](adr/0010-play-page-decoration-in-3d-function-in-2d.md))。
装饰层可以遮挡界面元素,但被遮挡的东西必须在别处有等价路径;装饰整层消失时,
应用功能完好无损。

**屏幕说什么,耳朵就听什么。** 点歌先换界面:旧歌立刻停,新歌名与封面立刻上,
播放页挂加载态,声音几秒后进来(见 CONTEXT「队列」)。同一条原则的另一面:
换歌时封面、歌词、点云都不留上一首的内容等新内容,旧图配新歌比空着更误导。

**出问题的状态自己开口。** 断流停在原地并给一条跨页横幅,文案先说发生了什么,
探明之后再说是哪一种([`adr/0013`](adr/0013-a-broken-stream-is-a-reportable-ending.md))。
静默失败等于把排查成本转嫁给用户。

## 结构:导航与页面

主导航只有 Home 与 Music 两个 tab,导航位是稀缺的。Music 页内部的四个去处
放在二级导航里:宽版式是可收缩的竖栏,紧凑版式是顶部一条分段条。播放页是
「正在播放」这个状态的展开形态,从控制条展开,由控制簇里的 ▼、安卓返回键、
桌面 Esc 收起,不占导航位(见 CONTEXT「播放页」)。

`crates/ui/slint/` 按职责分:

| 文件 | 职责 |
|---|---|
| `app.slint` | 主窗口:导航、页面装配 |
| `musicnav.slint` | Music 页的二级导航 |
| `tracklist.slint` | 一列可滚的曲目,搜索/推荐/歌单详情共用 |
| `playlists.slint` / `artists.slint` | 歌单列表、歌手视图 |
| `controls.slint` | 常驻控制条 |
| `login.slint` | 登录与注册 |
| `glass.slint` | 玻璃拟态基元:极光背景 + 玻璃卡 |
| `widgets.slint` | 通用小件(按钮、开关、卡片) |
| `theme.slint` | 色板,见下节 |
| `types.slint` | 界面与 Rust 之间的数据形状,字段是已格式化的字符串 |

## 版式

两种版式,由视口宽度决定,与端正交:< 600px 逻辑像素为紧凑版式(导航在底部),
否则宽版式(导航在左侧竖栏)。桌面把窗口拖窄就能看到移动端的样子,移动端排布
因此在桌面上可见、可验证([`adr/0007`](adr/0007-layout-mode-by-width-not-by-platform.md))。

## 主题与色板

明暗两套主题,由控制条上的日月开关切换。真相在 Rust 侧(`crates/ui/src/theme.rs`),
开关拨一下只发信号。

颜色全部收在 `theme.slint` 的语义 token 里,三族表面不混:

- **常驻界面**(window/base/surface/raised/hover):导航、列表、控制条、卡片,
  跟着明暗走。
- **沉浸层**(immersive*):播放页压在封面与点云上的那块底和字,两套主题下
  取值相同。底钉死,字就得跟着钉死。
- **错误横幅**(danger*):自成一套,便于单独调。

## 播放页与可视化

播放页的装饰在 3D、功能在 2D([`adr/0010`](adr/0010-play-page-decoration-in-3d-function-in-2d.md))。
可视化的主体是封面点云:封面被采样成一片粒子,随本机即将播出的声音起伏,
没有封面时退回一片渐变色(见 CONTEXT「封面点云」)。视觉预设当前只有「封面」
一档,入口与 seam 留着,加档往列表里填([`adr/0014`](adr/0014-one-visual-preset-with-the-seam-left-in-place.md))。

可视化只在「播放页展开 ∧ 正在播放 ∧ 窗口聚焦」时渲染,任一条件不满足即完全
停止:暂停定格在最后一帧,收起与失焦零重绘。

## 硬规则

都是违反过、且违反必出问题的,改 UI 前过一遍:

1. 新颜色进 `theme.slint` 的 token,不在别的 `.slint` 里写字面色。例外只有
   图形性绘制(日月开关那幅画)与调试读数。
2. 版式由宽度决定,不由端决定。不写「安卓 = 底部导航」式的分支。
3. 可视化不承载功能,被它遮挡的元素必须在别处有等价路径。
4. 播放页不新增只能在这里完成的操作。
5. UI 依赖 app-core 的方向永久单向,反向禁止(见 CONTEXT「UI 层」)。
