# UI 设计

界面的设计原则、结构现状,以及改界面前必须过一遍的硬规则。术语的定义在
[`CONTEXT.md`](../CONTEXT.md),每条决策的来龙去脉在 [`adr/`](adr/),这里只讲
它们合起来构成的那个设计。

当前设计来自 2026-08 的整体改版(Claude Design handoff,规格全文在
[`design/handoff-readme.md`](design/handoff-readme.md),shader 分层拆解在
[`design/handoff-shaders.md`](design/handoff-shaders.md),原始设计稿归档在
[`design/设计范围确认.zip`](design/设计范围确认.zip))。本文件与 handoff 冲突时,
以本文件为准。
实现进度挂在 [issue #56](https://github.com/yebei199/osmosis/issues/56)。

## 原则

**功能与氛围分家。** 操作类功能(播/暂/切/进度)由常驻控制条承载;播放页只管
沉浸与氛围,不新增任何只能在它里面完成的操作([`adr/0010`](adr/0010-play-page-decoration-in-3d-function-in-2d.md))。
装饰层可以遮挡界面元素,但被遮挡的东西必须在别处有等价路径;装饰整层消失时,
应用功能完好无损。

**屏幕说什么,耳朵就听什么。** 点歌先换界面:旧歌立刻停,新歌名与封面立刻上,
播放页挂加载态,声音几秒后进来(见 CONTEXT「队列」)。换歌时封面、歌词、点云
都不留上一首的内容等新内容:旧图配新歌比空着更误导。

**出问题的状态自己开口。** 断流停在原地并给一条跨页横幅,文案先说发生了什么,
探明之后再说是哪一种([`adr/0013`](adr/0013-a-broken-stream-is-a-reportable-ending.md))。
静默失败等于把排查成本转嫁给用户。

**界面上没有摆设。** 瓦片只放真实存在的应用,开关只在背后有数据时出现,
统计只画真数字。视觉可以先于功能落地,谎报状态的控件不可以。

## 壳与导航

Osmosis 是承载多个应用的壳,音乐是第一个应用(见 CONTEXT「壳」「应用」)。

- **Home 属于壳**:画成应用启动器,3D 瓦片场浮在场景里,当前只有 Music
  一张真瓦片加一个「＋装一个」空槽([`adr/0024`](adr/0024-home-is-the-shell-launcher.md))。
- **迷你播放条跨应用常驻**:悬浮在底部,封面、曲名、环形播放键、下一首。
  在任何应用里都能控播放,这是「壳」概念的具体体现。
- **宽版式导航**:左侧 76px 图标栏,Home 与 Music 在上,个人与设置沉底。
- **紧凑版式导航**:底部 48px 四项(Home / Music / 搜索 / 我的),迷你播放条
  浮在它之上。
- 播放页不占导航位,仍从控制条展开(见 CONTEXT「播放页」)。

## 音乐页:卡墙与列表

音乐页主视图是 3D 卡墙:当前一批曲目的封面卡在深度上散开,拖动旋转、滚轮推拉、
单击浮起、双击播放。列表与卡墙是同一批卡的两种摆法,切换只是深度插值,不换页面
([`adr/0025`](adr/0025-card-wall-is-the-music-main-view.md))。
无 GPU 的构建(web / iOS 默认)退回列表视图。

次级入口(每日推荐 / 我的歌单 / 最近播放 / 红心)是标题行右侧的一排胶囊。
卡墙的列距行距按容器尺寸计算,不写死像素:原稿里两处卡墙用了两套坐标,
跨尺寸复用会错位。

## 版式

两种版式,由视口宽度决定,与端正交:< 600px 逻辑像素为紧凑版式,否则宽版式
([`adr/0007`](adr/0007-layout-mode-by-width-not-by-platform.md))。桌面把窗口
拖窄就能看到移动端的样子,移动端排布因此在桌面上可见、可验证(`just shot 420`)。

紧凑版式的要点:卡墙降到 2 列且相机后撤(`render3d` 的 `pullback`);播放页
体素平面缩到 220px,控制簇只留上一首 / 环形键 / 下一首;个人主页统计卡 2×2;
设置页分组导航折叠成整块卡片流;触摸目标不低于 44px。

## 主题与色板

明暗两套主题,外加「跟随系统」:设置页三选一,存储是三值枚举
(`api::settings`),真相在 Rust 侧(`crates/ui/src/theme.rs`)。跟随系统的
检测当前只有桌面端实现,其余端按深色处理。

颜色全部收在 `theme.slint` 的语义 token 里,具体值以该文件为真相。三族表面不混:

- **常驻界面**(window/base/surface/raised/hover):导航、列表、控制条、卡片,
  跟着明暗走。绿色系:深色底往墨绿走,浅色底往纸绿走。
- **沉浸层**(immersive\*):播放页压在封面与点云上的那块底和字,两套主题下
  取值相同。底钉死,字就得跟着钉死(`crates/ui/tests/theme.rs` 守着)。
- **错误横幅**(danger\*):自成一套,便于单独调。

**绿是唯一的强调色**([`adr/0023`](adr/0023-green-is-the-only-accent.md))。
`accent` 深色下 `#8fc46a`、浅色下 `#4f7a3f`;绿色明度高,压在它上面的
`accent-text` 是深墨而非近白,对比度约 9.4:1。`accent-ink`(中性底上表示选中的
字与图标)仍随主题翻转。

**副色板 12 对**只用于封面占位、卡墙卡片、波形条、统计数字:一屏里颜色可以
很多,「重点」永远只有绿。取用规则 `hues[index % 12]`,渐变从亮色到深色。
真实封面到位后,它们只作为加载前的占位与失败兜底。

## 字体

| 角色 | 字体 | 说明 |
|---|---|---|
| 中文大标题 | 思源宋体 Heavy 子集 | 「每日推荐」这类页面标题与播放页歌名 |
| 拉丁与数字大标题 | Caprasimo | 无中文字形,中文场景一律走思源宋体 |
| 正文与界面 | Figtree | 中文回落到系统字体或 cjk-subset |
| 时长、进度、版本号、标签 | DM Mono | 一切等宽场景;等宽不再是全局观感 |

子集管线在 `just font-subset`;硬编码中文必须落在子集里,
`cargo test -p ui` 的 glyph 测试守着。

## 播放条

环形进度播放键取代通栏条:外圈是 conic 进度环,内圈是 `surface` 实心圆加
accent 图标,进度本身就是环,不再需要常驻细线;精确拖动时 hover 条身浮出一条
4px 细轨。条身是悬浮胶囊(桌面 62px 高、居中离底 22px),内容顺序:
封面 · 曲名/歌手+时间 · 上一首 · 环形键 · 下一首 · 随机/音量/展开。
移动端复用同一枚环形键。

## 播放页与可视化

播放页的装饰在 3D、功能在 2D([`adr/0010`](adr/0010-play-page-decoration-in-3d-function-in-2d.md))。
可视化的主体是封面点云(见 CONTEXT「封面点云」)。功能层收成一枚 72px 胶囊
控制簇:红心 · 上一首 · 环形键 · 下一首 · 随机 · 时间读数。歌名用大标题字体,
歌词卡的 z 抬到位移峰值之上,粒子全部从字后走。

歌词页从播放页横向滑出,点云退成背景光;当前行无模糊,前后行按距离给景深。
逐字与翻译的开关只在对应数据存在时显示。

可视化只在「播放页展开 ∧ 正在播放 ∧ 窗口聚焦」时渲染,任一条件不满足即完全
停止:暂停定格在最后一帧,收起与失焦零重绘。

视觉预设当前只有「封面」一档,入口与 seam 留着([`adr/0014`](adr/0014-one-visual-preset-with-the-seam-left-in-place.md))。

## 硬规则

都是违反过、或原稿里点名会出问题的,改 UI 前过一遍:

1. 新颜色进 `theme.slint` 的 token,不在别的 `.slint` 里写字面色。例外只有
   图形性绘制(日月开关那幅画)与调试读数。
2. 版式由宽度决定,不由端决定。不写「安卓 = 底部导航」式的分支。
3. 可视化不承载功能,被它遮挡的元素必须在别处有等价路径。
4. 播放页不新增只能在这里完成的操作。
5. UI 依赖 app-core 的方向永久单向,反向禁止(见 CONTEXT「UI 层」)。
6. 绿是唯一的强调色。副色板绝不用于按钮、选中态、链接、状态色。
7. 任何效果都不允许让静止画面每帧重绘:3D 走 `render-active` 门,播放页 warp
   走「展开 ∧ 播放 ∧ 可见」,转场走导航选中器,动态极光按钮走「前台 ∧ 可见 ∧
   用户没关」。
8. 界面上不放假东西:假应用瓦片、无数据的开关、编造的统计都不上屏。
