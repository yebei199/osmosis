# Shader / Bevy 效果 · 八个方案的分层拆解

对应设计稿 `Osmosis 播放器改版.dc.html` 的 `#2a` … `#2i`。每个方案在设计稿里都有一张卡：左边是会动的 CSS 近似（只表达观感与节奏），右边是分层拆解。**近似不是实现** —— 参数以本文件为准。

所有效果都必须挂在仓库既有的省电门下：3D 场景走 `render-active`，播放页 warp 走「展开 ∧ 播放 ∧ 可见」，导航选中器走转场门。**没有任何一个效果可以让静止画面每帧重绘。**

## 建议顺序（从便宜到贵）

| 顺序 | 方案 | 改动面 | 理由 |

| 1 | §8 grain + 扫描线 | 一个全屏后处理 pass | 十几行 WGSL，零架构改动，"略微复古"最便宜的一笔 |

## §1 换歌过渡 · 体素塌落重聚（`#2a`）

现状是硬切。

1. 顶点着色器同时持有**上一首**与**下一首**两张封面纹理，位置与颜色按 `t ∈ [0,1]` 做 `mix`。
2. 中段（`t` 约 0.25–0.75）把位置换成 **curl noise 流场**，颜色暂时脱离网格 —— 这是"散开"的观感来源。
3. 回落用 `smoothstep` 错峰：每颗粒子的延迟 = 归一化的到中心距离 × 0.9，中心先落、边缘后落。

总时长 900ms。同一个 mesh、同一个 draw call，只多一张纹理与一个 uniform。

**边界**：换歌比过渡快时（连按下一首）直接把 `t` 重置为 0 并换纹理，不排队。

## §2 音频驱动位移 · 频谱即高度场（`#2b`）

`src/viz.rs` 已经有音频载荷的取帧 helper 和 `VizControls` / `VizFrame` 这条 seam，**目前没有消费方**。接上即可，无新架构。

1. **低频（0–4 bin）** → 整片起伏，慢，做"呼吸"。
2. **中高频** → 只抖顶面 1–3px，做"颗粒"。
3. **位移后必须重算法线** —— 不重算的话高光不跟着动，起伏在画面上读不出来，白算。

wasm 侧数据源恒空，取帧代码无平台判断（`viz.rs` 已经这么写了），此时退化为静止点云，不报错。

---

## §3 列表 → 播放页 · 相机推近（`#2c`）

把"3D 是一个页面"改成"3D 是一条贯穿的深度轴"。

1. 列表行的封面**本来就是** 3D 场景里的一张卡，2D 只画占位（或干脆不画）。
2. 展开 = 相机 dolly + 卡片 `rotateX` 展平，Slint 那层同时淡出。420ms。
3. **落位之后才起点云**，否则相机运动与点云位移两套位移叠在一起，看起来像抖。

竖视口相机要后撤（`render3d` 的 `pullback`），这是 ADR-0007 外溢到渲染层的唯一一处。

---

## §4 封面取色喂极光（`#2d`）

1. 封面缩到 16×16，k-means 取 3 色，**丢掉近灰的**（饱和度低于阈值的直接弃，否则一堆脏灰）。
2. 三色喂 `glass.slint` 那三团光斑对应的 uniform，色相锁在封面上。
3. 换歌时 uniform 用 400ms 插值，不硬跳。

**这条同时解决了配色问题**：副色调的丰富度由歌决定，不用手配色板；绿仍然是唯一的强调色，变的只有背景。

---

## §5 玻璃真折射 + metaball 进度（`#2e`）

Slint 至今没有 backdrop blur（`docs/slint/visual-effects-and-shaders.md`），所以 Home/Server 那两页的玻璃是"半透明 + 厚度 + 高光"，不会真的模糊背景。**但播放页的玻璃条压在 3D 像素上** —— `crates/render3d/src/glass.rs` 那个 pass 能采样背后的帧：

1. glass pass 采样场景纹理 → 真模糊 + 边缘色散。
2. 进度滑块用 `lead`（快）/ `lag`（慢）两个圆做 smooth-union，拖动时拉出胶着的颈 —— **直接复用 `nav_glass` 的 metaball shader 与省电门**，只换几何来源。
3. 功能层仍然是 2D、不参与遮挡（ADR-0010 不可破坏）。

---

## §6 歌词体积景深（`#2f`）

1. 歌词卡 z 抬到位移峰值之上（现有 `CARD_ANCHOR.z` 已是 1.8），粒子一颗不少、全从字后面走。
2. 前后行按 `|Δz|` 给 **CoC 半径**做真景深，而不是贴一层固定模糊。
3. 换行时 z 插值，字像从远处走上来。

**前提不变**：歌词在别处没有等价路径，被盖住就是读不到，所以永远不能被遮挡。曾经试过让粒子按歌词包围盒绕开 —— 会在点云里横贯一条空带,已回退,别再试。

---

## §7 状态即视觉 · 缓冲 / 断流（`#2g`）

1. **缓冲**：位移场加高频噪声 + 轻微 CoC，像信号不稳。跟着 `audio::SeekState` 的轮询走。
2. **断流**：saturation uniform 3s 降到 0.06，声音停在哪儿画面就冻在哪儿。
3. 错误横幅**降级**成一行小字，不再压在画面正中 —— 状态先被看见，再被读到。

配合 ADR-0013「断流是一种可上报的结束」。文案仍归 `describe_stream_loss`，可见性仍归 `.slint` 里那句 `if banner-text != ""`，`tests/banner.rs` 继续守着。

## §8 全局 grain + 扫描线（`#2h`）

> 2026-08-13 结案（#74）：扫描线与噪点已移除，复古质感与产品方向不合。第 3 条的 vignette 留在沉浸层。

1. 全屏后处理：hash 噪声按帧号变，overlay 混合，**强度 0.03–0.06**（再高就脏）。
2. 扫描线 1px 亮 / 3px 暗，亮度 −2%，**只在沉浸层开**，常驻界面不加。
3. 一道极轻的 vignette 收边，把注意力拢回中心。

一个 fullscreen triangle、十几行 WGSL。设计稿 `#2h` 那张卡是左右分屏对比（左关右开），可以照着调强度。

## §9 光带按钮 · 无限流动的色散光带（`#4a` `#4b` `#4c` `#4d`）

按用户提供的参考图（黑底胶囊 + 一条穿过按钮的彩色光带）重做。**设计稿里那几颗按钮是真的着色器在跑** —— 见 `aurora-button.js`（WebGL/GLSL），与要写的 WGSL 是同一套数学，逐行对应。

### 五步，全在片元里，没有贴图

1. **流场中心线**：三条不同频率的正弦叠加，相位里加 `t` —— 无限流动来自这里，没有循环点。
   ```
   center(x,t) = 0.50
     + 0.150*sin(2π*(x*0.80) + t*0.60 + seed)
     + 0.085*sin(2π*(x*1.70) - t*0.45 + seed*1.7)
     + 0.045*sin(2π*(x*3.10) + t*0.90 + seed*0.6)
   ```
2. **带宽呼吸**：`width(x,t) = 0.052 + 0.030*sin(2π*(x*1.30) - t*0.50 + seed)`。窄处更亮 —— 参考图里那种被挤扁的高光。
3. **逐通道色散**：R/G/B 各按 `±disp` 偏移采样。`disp` 随中心线**斜率**增大（`0.006 + 0.030*clamp(slope*0.16,0,1)`）—— 所以**只有拐弯处出彩虹边，直段是白的**。这是参考图最关键的一点，做成全局固定色散就会糊成一团彩虹。
4. **方向性动态模糊**：沿流动方向取 8 个样本加权累加（`x - i*0.0055`，权重 `1 - i/9`）。这是"糊开的丝带感"的唯一来源。
5. **裁形**：圆角矩形 SDF 做遮罩，顺带取一圈 `rim` 亮线。之后叠白热核心 `pow(core,3)*1.9` 与外圈辉光。

### 两版配色，用在哪

| 版本 | 色相 | 建议用途 |
| --- | --- | --- |
| **4a 全光谱** | 色相沿 x 与 t 推移，饱和 0.85 | **只用于 Home 的「＋ 装一个」空槽**这类一次性高光 |
| **4b 收进绿板** | 色相锁在 0.30±0.13（绿→青→黄绿），色散边混一点紫 | **主界面一律用这版** |

理由：全光谱好看，但它会变成界面里的第二个强调色，把"绿是唯一重点"这条规矩破坏掉。

### 在本仓库的落点

**不是 Slint 的 `Rectangle`** —— Slint 没有自定义着色器入口。走 `crates/render3d` 的**独立 wgpu pass**，与导航液态玻璃（`nav_glass`）**完全同构**：Slint 只出几何与 hover 状态，shader 渲到一张纹理，Slint 合成它。照着 `nav_glass.rs` 的 `NavGlassControls` 那套 POD seam 做一份 `AuroraButtonControls` 即可（ui 与 render3d 刻意互不依赖，镜像分离）。

### ⚠️ 不要照抄设计稿的结构

设计稿为了演示，**一颗按钮一个 WebGL context + 一条 rAF**（共 10 颗）。真实实现**必须合批**：

- 所有极光按钮渲进**同一张图集纹理**，一个 pass 画完，每颗只差 `seed` 与 `speed` 两个 per-instance 参数。
- 省电门与 `nav_glass` 同款：**只在 hover 动画进行中、或静息振幅未收敛时重渲**；收敛后复用上一帧纹理。窗口失焦 / 不可见即停。
- 静息态振幅 0.12（约一成多亮度），hover 用 `amp += (target-amp)*0.09` 收敛到 1.0，约 90ms 到位。

### 成本

128×420 的按钮 = 5.4 万像素 × 8 次采样，桌面可忽略。移动端若吃紧，先把动态模糊的采样数从 8 降到 4（观感损失最小），再降静息态帧率到 30。

### 开关

设置页「外观」有一项「动态极光按钮」（默认开）。关掉 = 纯色实底，功能完全不变。无 GPU 端直接走关闭分支。

## 通用约束

- 不新建渲染管线：遮挡复用 render3d 既有的双图设施（场景 + 遮挡层）。
- `preset` 那条 seam 留着（`.slint` 的 `viz-preset` → `VizControls` → `VizFrame` → uniform），当前唯一合法值仍是 0（ADR-0014）。越界兜底也留着 —— 那是跨层信任边界，与档位多少无关。
- 无 GPU 端（web / ios 默认构建）粒子为空图，自动退回 warp 形态；本文件所有效果都必须在这条路径上**静默降级而不是报错**。


## §10 按钮变体（第五轮新增，`prism` 为 #83 追加）

六类共用一个片元程序，`uVariant` 分支。真机 WGSL 同构，四阶 fbm 足够按钮尺寸使用，不要照搬参考实现的六阶。

| variant | 数学 | 开销 | 用在哪 |
| --- | --- | --- | --- |
| `ribbon` | 正弦流场中心线 + 逐通道色散 + 方向性动态模糊 | 中 | 一次性高光 |
| `nebula` | 域扭曲 fbm（六次 fbm 调用）+ 星点格 + 指针涡旋 | 高 | Home「＋ 装一个应用」，一屏一颗 |
| `fluid` | 域扭曲 + softBlob plume + `reveal` 沿 x 开闸 + spec/caustic | 中高 | 播放页长条、正在播放胶囊 |
| `glass` | 低密度底 + 折射亮边 + 焦散高光 | 低 | 次要按钮，可整屏铺 |
| `progress` | `fluid` + 进度填充遮罩 + 交界处呼吸亮边 | 中高 | 下载、导入曲库、模型加载 |
| `prism` | 逐像素朝三棱柱三个面投射线（真透视，只对 y/z 除法）+ 面法线余弦压暗 + 棱边暗线，面上贴 `fluid` | 中高 | 播放控制条条身，随 `flip` 转面 |

关键约束：`reveal = smoothstep(0.055, 0.735, uv.x + (0.5 - broad) * 0.27 + …)` —— 左侧接近 0，长条按钮上的文字区不会被流体糊住。这条在 WGSL 版必须保留。

`prism` 因此有一条自己的约束：**每面取不同贴图段时只许错开 v，绝不许错开 u**。`reveal` 是按 `uv.x` 开的闸，动了 u 等于把闸挪走，转到面 B、面 C 时流体会漫过条身左边的曲名与时间，字直接读不出来（实拍踩过）。

`prism` 的张角（`sy = (uv.y - 0.5) * 1.8`）是唯一的调节旋钮：条身宽是高的九倍，张角小了三个面挤成一条缝、看不出在转，大了侧面吃掉整条。另外，**停在某一面时棱柱正对相机、看上去本就是平的**——3D 只在转的过程中现形，静态截图验不了这个变体，要抓转场中的帧。

参考实现：域扭曲 + plume + reveal 的做法来自 fluidglass-ui 的 canonical fragment shader；星云与柔光带来自 nebula-capsules 的 `src/cosmic-shader.js`。两者都只取数学，配色一律走 Osmosis 绿板。


## §11 侧栏水滴导航（第六轮）

指示器不是一个元素，是三颗球共处一层：头球 52×52 / 尾球 38×34 / 小水滴 20×18，追随系数 0.30 / 0.19 / 0.13。同一个目标位置，系数不同就天然拉开先后，中途被拉出细颈再断开、落下合并。

- **粘合**：Web 侧用 SVG 滤镜（`blur(7)` + 高对比 alpha 矩阵）。Slint 侧没有滤镜链，用 SDF：三个圆角矩形距离场取 smooth-min（k≈14px），更省也更可控。
- **拉伸**：每帧 `scale = 1 + min(0.42, |v| * 0.028)`，另一轴取倒数保面积。按实时速度算，所以相邻切换只轻轻一颤，跨四格才拉成细长水滴。
- **积分按真实时间**：`f = 1 - pow(1 - k, dt / 16.67)`，帧率变化不影响动画时长。
- **驱动**：不要用 CSS 过渡或纯 rAF —— 宿主 document 处于 hidden 时两者的时钟都冻结。用定时器与 rAF 竞速的循环直接写 transform，静止即停。
- 横向（移动端底部导航）只是把位移轴与拉伸轴对调，系数共用。
