# 卡墙改双向无限 + 卡面美化与闪卡

## 1. Change Purpose

卡墙原本只有一条横轴:竖向拖动只改俯仰角,横向拖到底就是空白。这次把它
改成**环面**—— 两轴都能拖、都无限循环,拖到哪都还是一墙卡。顺带补上卡面
本身的质感:圆角之外加细描边和一圈柔和投影,正在放的那一张换成会流动的
闪卡。决策更新在 [`adr/0025`](../../adr/0025-card-wall-is-the-music-main-view.md)。

## 2. Change Scope

- `crates/ui/src/wall.rs`:`layout` 多收一个卡数参数,行列数按**场区长宽比**
  分配(横场列多、竖场行多),周期按「至少一屏 + 一张卡」撑开;`card_pose`
  只给网格里的绝对位置,不再自带居中偏移。圆角烘焙换成 `bake_card`:
  圆角 + 细描边 + 投影一次烘完,输出比输入四周各大 `CARD_PAD`。
  另有 `bake_blank`,给还没封面的格子用。
- `crates/ui/src/wall/camera.rs`:`WallCam` 加 `pan_y`/`vel_y`,拖动两轴都平移;
  删掉格点吸附与 `dolly` 字段(滚轮不再推拉镜头);`world_pose` 多收布局,
  在里面做环面回绕 —— 回绕之后卡的坐标已是「相对镜头」,`project` 与
  render3d 的相机因此都不再需要平移。速度改为跨帧指数滑动平均,
  整场姿态角改为只转卡片朝向、不转卡片位置(见 §3 的两条抖动契约)。
- `crates/ui/src/wall_drive.rs`:seam 去掉 `pan_x`、加上 `foil`(在播的那一格)
  与 `WallCover.blank`(这张是不是空白卡面);
  方片尺寸连投影余量一起放大;`collect_covers` 改烘卡面,并给没封面的格子
  先挂一张空白卡面。滚轮回调按 dpr 换算成物理像素。
- `crates/render3d/src/foil.rs` + `foil.wgsl`:新增。闪卡材质 —— 余弦调色板
  绕出的彩虹干涉条纹,加一道周期更长的扫光,按帧计数常驻流动,靠底图 alpha
  收在卡面内。
- `crates/render3d/src/wall.rs`:相机 x 恒 0;每帧把闪卡材质挂到该挂的那一格
  (增删 `MeshMaterial3d` 组件,不是同时挂两种);卡片材质两端统一 `Blend`。
- `crates/ui/slint/globals/player.slint` + `src/music/transport.rs`:新增
  `Player.now-id`,卡墙据此挑出在播的那一张。`tracks` 里的 `loading` 只在取流
  那几秒为真,指不了整段播放。
- `crates/ui/slint/wallview.slint`:提示文案改「滚轮上下」。
- `crates/ui/src/wall/tests.rs`:17 条单测。新增的几条盯住这次的真需求 ——
  拖过一个周期回到原处、任意方向拖多远屏幕上都还有卡、命中测试跟着回绕走、
  周期罩得住视口、网格形状跟着长宽比走。

## 3. Contract

- **卡墙没有边**。两轴周期分别是 `cols × col_pitch` 与 `rows × row_pitch`,
  且都不小于「一屏 + 一张卡」—— 周期比视口小的话取模会把所有卡挤到屏幕中间。
  每张卡仍然只有一个实体:滑出右边的那张就是从左边进来的那张。
- **滚轮 = 竖着划一下**,与移动端同一套语义。推拉镜头不再挂在滚轮上,那一档
  只剩双击进播放页时的自动 dolly。
- **松手自由停**,不吸附格点:环面上没有「一屏」可对齐,停在哪都成立。
- **只有在播的那一张会闪**。闪光是「在播」的视觉信号而非装饰,所以没有歌在放、
  或在放的那首不在这批卡里时,一张都不闪。
- **闪卡加光看亮度余量**,不是纯加性叠加:亮处只做零均值的色偏,暗处才补整段
  彩虹。封面才是内容,闪卡是它上面的一层膜 —— 纯加性会把浅色封面推到过曝,
  线条和字糊成一片白(真机实拍确认过)。
- 卡面纹理比卡本身四周各大 `CARD_PAD`,方片按同比例放大;**命中测试仍按卡面
  算**,点投影那一圈不算命中。
- **安卓两端不同的只有透明度那一档**,几何、回绕、卡面烘焙全部共用一份代码。
- **速度是跨帧平滑值,不是最后一帧的指针位移。** 指针位置只在 `moved` 事件里
  镜像过来,循环却每帧跑:鼠标上报率低于帧率时有的帧位移是 0。姿态角直接取
  瞬时速度的话会逐帧在满偏与归零之间跳,整墙看着在抖;松手前那一帧若恰好是
  空帧,惯性还会整个丢掉。平移仍逐帧吃满位移,平滑只作用在速度上。
- **整场姿态角只转卡片朝向,不转卡片位置。** 曾经是绕镜头旋转整个网格,那样
  yaw 会把 x 混进 z,gx 回绕一个周期时深度跟着跳 `span_x·sin(yaw)`,投影缩放
  突变,卡片带着尺寸变化凭空出现在屏幕里 —— 边距开多大都补不回来,因为跳的
  是深度不是位置。
- **回绕必须发生在屏幕外**,这是环面唯一的前提。周期因此按「最远那层卡上的
  视口 + 两张卡」算,竖向还要绕相机下移后的中心而不是场心。代价是墙比原来
  稀疏约两成:三十张卡摊在 1.2 屏见方的周期上。
  `dragging_never_makes_a_visible_card_jump` 逐帧盯住这条 —— 它比盯某个角度
  靠谱,卡在屏幕上的位置是姿态、回绕、投影共同的结果。

## 4. Known Cuts

- 相邻重复周期之间不做错位排列。三十来首歌的周期已经比一屏大得多,滑到撞见
  重复要好几屏;错位要付的是坐标→曲目映射和命中测试都绕一层。
- 卡数太少时(个位数)网格会明显稀疏 —— 周期被撑到一屏大,而卡不够填。
  ponytail:等真出现「推荐只回三首」再考虑按格子取模复用曲目。
- 安卓退回 `AlphaMode::Mask(0.5)`。曾试着两端统一走 `Blend`,在努比亚平板上
  复验的结果是**整面墙一张卡都画不出来** —— 而同一批曲目在列表里封面齐全,
  卡墙纹理也照常导入。换成 `Mask` 立刻全部显示。换了设备、换了芯片,
  adr/0012 记的那个 Adreno 坑还在。
  代价是安卓上没有投影:投影峰值 alpha 是 0.42,整段低于 0.5 的门槛,被 alpha
  测试干净地丢掉,而不是切成硬边光晕。圆角也从软边变硬边。描边不受影响 ——
  它长在 alpha 为 1 的卡面里。
- 闪卡在桌面上不是负担:墙 + 闪卡一起,整帧 8.41ms(119fps)= 回调 3.85ms +
  Slint 渲染 1.09ms + 空等 3.44ms,循环还剩三分之一的余量。墙本来就恒满帧渲染
  (change_log 2026-08-11 always-on-rendering),多出来的只是一张卡的片元开销。
  **安卓上的闪卡没单独量过**,也没在真机上看过它的样子:卡墙本身已在努比亚
  平板上验过,但那次没有歌在放。
