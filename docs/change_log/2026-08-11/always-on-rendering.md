# 前台恒满帧,后台暂停(推翻硬规则 7)

旧省电门的哲学是「静止画面零重绘」:每个动效各自维护收敛判定,收敛即冻结,
靠事件把渲染循环叫醒。它带来一整类"没人叫醒"的 bug(封面异步到货要 COVER_PATIENCE
热身、纹理首帧未就绪不许冻、按下要 poke 一声),每加一个动效都要重新发明
一套冻结与唤醒。改版后的取舍是:前台的流畅与代码的简单优先于静止时的功耗。

## 新语义

- 渲染通知回调每帧无条件 `request_redraw()`,循环自持在 vsync 节拍上。
- 后台即暂停:安卓切后台、桌面最小化时平台停发重绘,循环自然停摆,
  回前台由平台重启第一帧。
- 桌面失焦不算后台:可见即前台,失焦照转(音乐播放器常被摆在一旁看
  可视化)。遮挡信号拿不到的平台照转,满帧优先。
- 暂停播放时点云照样动:没音频就按环境节奏慢转。播放页的噪点层同理,
  不再分"播放中跳相位 / 暂停静止"两档。

## 拆掉的东西

- `wall_drive`:busy 判定、`rendered_settled`、`COVER_PATIENCE` 热身、
  `image_missing` 特例、`wall-poke` 唤醒回调。
- `aurora_btn`:`step()` 的"要不要重渲"返回值与冻结账目,只留振幅收敛数学。
- `lib.rs`:卡墙与 warp 门里的 `is_active` 失焦判定、`.slint` 的 `viz-active`
  (展开 ∧ 播放)谓词。warp 门只剩「播放页展开」。

## 留下的东西

- 导航侧栏液态玻璃选中器的纹理缓存:静止时不重算那张纹理。这是工作量
  缓存,不是会冻住动画的门 —— 窗口照样每帧重绘。
- 歌词只在换行时推送:每帧无脑 set 会把属性标脏,那是纯浪费,与省电无关。

## 验法

桌面:fps 读数在静止页面上持续走(旧行为是归零)。真机:SurfaceFlinger
present 时间戳恒满帧(测法见 ready_issue/slint-wgpu-present-order.md)。
功耗代价是明知的:前台挂着不动也在烧 GPU,这正是这次取舍买单的部分。
