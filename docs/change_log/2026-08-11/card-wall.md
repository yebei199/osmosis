# 音乐页主视图改 3D 卡墙

## 1. Change Purpose

改版(#56)的压轴件 #66,决策在 [`adr/0025`](../../adr/0025-card-wall-is-the-music-main-view.md):
挑歌环节开进「Slint + Bevy 同一块显存」的架构主线,曲目封面成为 3D 场景里的物体。
卡墙是每日推荐分区的默认视图;列表是同一批卡塌回 z=0,不是第二个页面。

## 2. Change Scope

- `crates/ui/src/wall.rs`:新增。卡墙的几何真相 —— 布局按容器尺寸推导
  (参考场 904×432 的比例,坐标不跨尺寸复用)、逐卡确定性散布、拖动惯性
  (阻尼 0.92)与格点吸附、滚轮 dolly 行程限制、420ms 塌回插值、双击 dolly、
  投影与命中测试、圆角 alpha 烘焙。纯数学,10 条单测。
- `crates/ui/src/wall_drive.rs`:新增。每帧驱动与 slint 绑定:指针镜像变成
  相机状态,封面缩略图取像素、烘圆角、经 seam 上传(每帧限 6 张);
  dolly 落位才放歌开播放页;全部收敛即冻结。
- `crates/render3d/src/wall.rs`:新增。bevy 侧只摆 ui 算好的世界位姿:
  unlit 方片 + 封面纹理,渲染层 1 与点云隔离,自己的相机与离屏目标,
  与点云入口互相关灯。相机无旋转,与 `ui::wall::project` 严格同构。
- `crates/ui/slint/app.slint`:音乐页加视图开关(列表/卡墙)、卡墙场区
  (纹理 + TouchArea 镜像),墙可见时列表让位。
- `crates/ui/src/lib.rs`:`run_with_renderers` 加第四个闭包(卡墙帧),
  渲染循环加卡墙门(墙可见 ∧ 播放页没开 ∧ 窗口聚焦)。
- `apps/desktop`、`apps/android`:Scene 改 `Rc<RefCell>` 给点云与卡墙两个
  闭包共用;新增卡墙 seam 平凡拷。
- `crates/ui/tests/wall_view.rs`:新增。开关只喊不置位、无 GPU 静默退列表、
  默认视图是墙。

## 3. Contract

- 无 GPU 构建(web / iOS)`wall-supported` 恒假,整套控件不实例化,列表照旧。
- 竖视口不做独立的相机后撤:透视距离与卡尺寸都随容器**宽**缩放,窄视口下
  卡与视野同比收窄,效果等价(与点云那台「不后撤」的相机是两回事,互不影响)。
- 省电门同仓库其余三道:静止的墙零重绘。

## 4. Known Cuts

设计稿 3b 里以下几样本轮没做:卡面左下角曲名(3D 内嵌文字另需一套字形管线)、
标题行与次级入口胶囊(现有 MusicRail 继续服役)、超过 36 张卡的分页翻找。单击浮起
做了深度抬升与提亮,没做设计稿里的完整高亮描边。

**2026-08-13 结案:这四项定为不做。** 它们当初是权衡之后砍的,不是排期不够;砍掉之后
用了两天多没有人提出缺失,而补做要付的是一套字形管线、一次布局重排和一层分页状态。
父 issue #56 已整体交付关闭,这四项不再另拆。哪天真有人要,照上面括号里那几句重新
评估即可,那时的前提多半也变了。
