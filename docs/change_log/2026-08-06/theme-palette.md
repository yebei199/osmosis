# 界面颜色收进一张色板

## 1. Change Purpose

控制条上那个日月开关管的是**随机播放**(`DayNightSwitch` 的注释写着「白昼(顺序播放)
⇄ 夜晚(随机播放)」)。那是借来的语义:画着太阳和月亮的开关,谁看都以为它管明暗。
后果是播放顺序在界面上没有一个认得出来的控件 —— 用户自己发现的。

要把日月开关还给明暗,得先有明暗可管。而在此之前**这个 app 没有主题层**:颜色
散在 9 个 `.slint` 里,133 处、67 种,其中 48 种只出现一次。

本轮只做色板本身,**行为不变**。接开关与浅色配色是后两步(#48)。

## 2. Change Scope

- `crates/ui/slint/theme.slint`:新增。20 个语义 token,深浅两列
- 8 个 `.slint` 的 112 处字面色换成 token:`app` 28、`widgets` 33、`musicnav` 14、
  `tracklist` 12、`controls` 11、`playlists` 6、`login` 4、`artists` 4
- `crates/ui/README.md`:补上这一层

**刻意没动的**:

| 位置 | 剩余 | 为什么 |
|------|------|--------|
| `glass.slint` | 14 | 极光与玻璃卡,属于 3D 那层,归 #48 的第 3 步 |
| `widgets.slint` | 6 | 日月开关那幅画(天空/太阳/月亮/陨石坑)是图形,不是语义 |
| `app.slint` | 1 | `#51cf66` 帧率读数,调试用 |

## 3. Implementation Process

1. 把 67 种色按用途归类,定 20 个 token。**不是一一对应的改名** —— 一次性的色往
   最近的语义上归,深色因此有肉眼难辨的位移。严格 1:1 的话浅色那套要配 67 个值,
   配不出来
2. 先只改 `controls.slint` 一个文件编译,确认 Slint 的 `darker()` / `with-alpha()`
   能用,再铺开剩下的 7 个
3. 逐文件写显式映射表替换,每个文件替换完当场断言"剩余字面色"符合预期

第 2 步那次探针撞上一个既有的坑:`cargo check -p ui` 单独跑必然报 5 个
`cannot find function load_image_from_embedded_data`。`git stash` 跑基线才确认那是
feature unification 的老问题,与本次改动无关 —— 验 `.slint` 要用 `cargo test -p ui`。

## 4. Key Diff / Core Functions

`theme.slint` 的三族表面,别混:

- **常驻界面**(`window`/`base`/`surface`/`raised`/`hover`):导航、列表、控制条、
  卡片。跟着明暗走
- **沉浸层**(`immersive`/`immersive-panel`):播放页压在封面与点云上的那块底。
  它存在的理由是让 3D 粒子读得出来,浅色下要不要跟着变亮是另一个问题
- **错误横幅**(`danger-surface`/`danger-line`/`danger-text`):自成一套,不跟别人
  共用名字 —— 共用了就没法只调它

强调色的三种状态由 `accent` 派生(`darker`),不各给一个 token:那是同一个决定的
三个亮度,分开写迟早有一个忘了改。

叠加色深浅两列方向相反:深色往上叠白(`#ffffff14`),浅色往下叠黑(`#00000014`)。
同一个语义。

## 5. Verification

- `cargo test -p ui` 127 条全绿,`cargo clippy -p ui --all-targets -- -D warnings` 干净
- 真实窗口截图(niri,1526×1668 逻辑像素):Home 页与 Music 页各一张,与改前对照
  ——导航栏、栏目高亮、列表行、封面、红心、时长、控制条,一处没走样
- **判据强度说明**:改前那张截的是「我喜欢的」,改后是「每日推荐」,所以是肉眼比对
  而不是像素 diff。色板收敛本来就允许位移,像素全等也不该期待

## 6. Difficulties

- 日月开关那六种色(天空、太阳、月亮、陨石坑)看起来最像"该进色板"的东西,实际上
  最不该进 —— 它们不是"某个语义在深色下的取值",是一幅画的颜料。混进去之后浅色
  那一列会被迫给太阳配一个"浅色版",而太阳没有浅色版
- 播放页与音乐页是两套底色(冷灰 `#0b0d13` vs 暖棕 `#140f0b`),不是随手写歪的:
  前者托着封面点云,后者是常驻界面。合并成一个 token 会在第 3 步炸开

## 7. Final Result

界面上每一个颜色都从 `Theme` 取。深色照旧,`dark` 先钉死为真。浅色那一列已经
写了一版占位值,但没有任何东西读得到它 —— 要等第 2 步把开关接上才看得见。

## 8. Risks And Follow-ups

- **浅色那一列没人看过**。它是照着深色反推的一版,对比度没验过。第 2 步接上开关
  之后必须逐屏看,尤其是浅底上的 `accent`(琥珀色在纸白上很容易糊)
- `glass.slint` 与 3 个 shader 还是深色写死的。浅色主题在第 3 步之前是半成品
- 那 20 个 token 说好的是"~16 个",实际落到 20。多出来的是沉浸层那族与错误横幅
  那族 —— 硬并进去会让两种表面共用一个名字
