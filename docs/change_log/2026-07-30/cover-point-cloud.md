# 播放页可视化换主体:浮空尘埃 → 封面点云

## 1. Change Purpose

播放页的粒子一直是照抄错了模块的产物。参照物 Mineradio 的
`02-visual/01-float-skull-backcover.js`(`createFloatLayer`)是它封面粒子系统**背后的
配菜** —— 一层与封面无关的浮空尘埃;真正的主体在同目录的
`00-pointer-cover-particles.js`:把封面按网格采样成点云,每颗取对应像素的颜色。

用户看参照物时说的「粒子特效」指的是后者。本轮把主体做出来,配菜删掉。issue #22。

## 2. Change Scope

- `crates/render3d`:`particles.rs` 删除,新 `cloud.rs` + `cloud.wgsl`;`lib.rs` 的
  内容重建与每帧驱动改写;README 同步。
- `crates/ui`:`cover.rs` 解码多出一路裸像素;`music.rs` 加 `CoverFeed`;`viz.rs` 加
  `VizCover`;`lib.rs` 在 seam 处取用;`app.slint` 删封面卡、歌词接管深度。
- `apps/desktop`、`apps/android`:seam 多传一个封面参数。
- `docs/adr/0012` 新增;`CONTEXT.md` 加「封面点云」词条。

## 3. Implementation Process

1. **点云本体**(2971db8,close #23):183² 颗粒子烘成**一个** mesh,自定义
   `Material` + WGSL 顶点位移,挂在既有的双相机遮挡设施下。无封面时走原版的默认渐变色,
   这一步就能独立上屏。
2. **封面像素接入**(close #24):同一次解码喂两处 —— 界面的封面卡与点云的采样纹理;
   只在换歌那一帧过 seam。保留上一首的纹理做颜色渐变,同一个计时器派生 burst 脉冲。

第 2 步里靠真实像素抓出三处错,都不是编译期能发现的:

- **v 方向反了**:格点 y 越大越靠画面上方,纹理 v 越大越靠图的下边。封面上下颠倒 ——
  上下对称的封面上看不出来,天空在上的那些一眼穿帮。补了一条测试钉住。
- **点尺寸钉的是像素**:视口一变,点与格距的比例就跑,点云散成一层网点而不是一张图。
  改成两者同在世界单位里(投影后比例恒定),并把网格从 183 提到 384 —— 平面铺满视口后,
  183 格的格距有二十来像素,眼睛拼不出图。
- **位移幅度没跟着平面放大**:平面从原版的 4.8 放到 12,位移还是照 4.8 调的绝对值,
  相对幅度缩水 2.5 倍。补了 `MOTION_SCALE`。

## 4. Key Diff / Core Functions

- `cloud::cloud_vertices`:烘一次就不动的顶点缓冲。每颗粒子四个顶点拼一个方片,
  带格点 uv(格心,不贴边)、角偏移、逐粒子随机数。角偏移借法线属性位。
- `cloud::CloudMaterial` / `cloud.wgsl`:SILK preset 的位移(中频两层 simplex 起伏、
  高频抖动、低频呼吸,全部只推 z)+ 封面采色 + 软边圆点。方片在**视图空间**摊开,
  粒子永远是正圆。
- `cloud::TrackTransition`:一个计时器派生两条曲线 —— 颜色渐变(0.9s 线性)与 burst
  脉冲(0.55s 平方衰减)。原版是两个各自衰减的 uniform,合成一个免得走散。
- `ui::cover::decode`:一次解码两个出口。点云那一路长边收进 512(`thumbnail` 盒式降采样)。
- `ui::music::CoverFeed`:待送的封面像素,取走即清空;没被取走就又换歌时直接顶掉。

## 5. Verification

- 单元测试:render3d 15 条(网格四角/uv 值域/v 方向/索引有界,换歌过渡四条),
  ui 25 条(含封面降采样三条、`CoverFeed` 两条),全绿。
- 真实像素验收(桌面 linux,niri,1908×2085):点云读得出封面(把截图与封面卡各降采样到
  6×6 比对,左右明暗同向);删掉封面卡后歌名与歌词居中成一组;网格随音乐起伏可见。
- 性能:`app.update()` 3.5ms/帧、整帧 10.3ms(97fps),147 456 颗粒子。作为对照,
  旧的浮空尘埃层 1300 颗在小米13 上是 36.75ms。
- 已知未覆盖:**android 未构建验证**,粒子数涨了 4.5 倍,真机发热读数尤其欠着;
  鼠标涟漪(#25)未做;其余视觉预设(#26)未做。

## 6. Difficulties

- 参照物的模块编号(`00-`、`01-`)是加载顺序,不是版本号。当初把 `01-float-skull` 读成
  「v1」,抄了配菜。教训与上一轮同一条:有源码就先读源码,别从截图反推。
- 三万多颗粒子不可能各是一个实体(1300 颗已经吃掉小米13 一帧的三分之一),必须烘成一个
  mesh 走顶点位移。这条逼出了 `docs/adr/0012`。
- 观感类的错全都要靠真实像素才看得见,而对话里显示的截图是缩放过的 —— 三处错里有两处
  是靠裁原始像素比对才确认的,不是靠看图。
- `cargo test -p ui` 单独跑会因为 slint 生成代码的 feature 不同而编译失败,要带上
  `-p app-desktop`(仓库既有的坑)。

## 7. Final Result

播放页的主视觉现在是封面本身:三万多颗粒子铺满视野,颜色逐颗取自封面像素,随三段频谱
起伏,换歌时颜色过渡并炸开一次。中间那张重复的封面卡删掉,歌词接管深度卡片的角色 ——
粒子仍从字的前后穿过,`docs/adr/0010` 的判据不变。

## 8. Risks And Follow-ups

- android 构建与真机发热读数持续欠着,且这一轮把粒子数从 1300 提到 147 456。
- 鼠标涟漪(#25)未做:播放页现在点哪都收起,那块 TouchArea 要改成驱动点云,
  收起改走控制簇里的向下三角。
- 其余视觉预设(#26)未做:滚筒、星球、唱片、星河、安魂、虚空。
- `docs/reference/play-page/` 仍是阶段性资产,播放页收尾时删除。
