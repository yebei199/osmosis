# 封面点云在小米13 上的读数

2026-07-30,小米13(fuxi,Adreno 730,MIUI),1080×2400 竖屏,充电中、电量 100%。
播放页展开、正在播放、封面档(preset 0),14.7 万颗粒子。

## 一、帧

| | `app.update()` | 整帧 | 其中回调 | 空等 |
|---|---|---|---|---|
| 冷启(重装后新进程) | 9.9ms | 15.2ms(66fps) | 10.2ms | 3.0ms |
| 温机约 1 分钟 | 8.3ms | 31.0ms(32fps) | 8.3ms | 21.0ms |
| 连续跑十分钟 | 14.5ms | 31.5ms(32fps) | 14.0ms | 14.3ms |

两件事分开看:

- **点云自己的开销**是 `app.update()` 那一列:8~15ms,随温度浮动。
- **帧率不由它决定**。31ms 那两行里,多出来的六毫秒全从「空等」扣掉,整帧纹丝不动;
  而冷启那一行整帧只有 15.2ms、空等 3ms,同样的 `app.update()` 却跑到 66fps。
  所以 32fps 不是点云压出来的,是**画面送出去那一侧**的问题。

  **不是帧泵。** issue #20 那条(`request_redraw` 只置标记、不参与超时计算)已经修好,
  补丁在我们 fork 里、也已合进上游([slint#12688](https://github.com/slint-ui/slint/pull/12688)),
  事件循环见 `pending_redraw` 就把超时归零,不存在人为下限。

  **嫌疑是屏幕刷新率。** `dumpsys display` 读到本机 `renderFrameRate 60.000004`、
  `mActiveSfDisplayMode` 为 60Hz,而 `peak_refresh_rate` 设的是 120 —— MIUI 按内容
  在两档间动态切。60Hz 一个 vsync 是 16.67ms,31ms 正好两个;120Hz 是 8.33ms,
  15.2ms 也正好两个。两档读数都精确落在「每两个 vsync 出一帧」上。`eglSwapBuffers`
  阻塞正发生在 AfterRendering 之后、下一次 BeforeRendering 之前,也就是我们记成
  「空等」的那一段。合起来的解释是:帧成本刚好越过 vsync 截止线,只能等下一个。
  **这条尚未验证** —— 锁住刷新率(`settings put system min_refresh_rate 120`)
  再测一轮就能坐实。

作为对照:被它替换掉的浮空尘埃层只有 1300 颗,却是 **36.75ms/帧** —— 那一版是
1300 个 bevy 实体、每帧 CPU 逐个写 Transform。现在 113 倍的粒子快 2.5 倍,
因为几何烘成了一份 mesh,位移全在顶点着色器里(见 `docs/adr/0012`)。

## 二、温度

十分钟连续播放,起点已是温机(前面装机、跑过一轮预设):

| | 起 | 十分钟后 | 差 |
|---|---|---|---|
| 电池 | 33.0°C | 38.1°C | +5.1 |
| gpuss-4 | 52.9°C | 57.7°C | +4.8 |
| cpu-0-0 | 51.1°C | 53.5°C | +2.4 |

机身温手不烫,没有触发系统的降频告警。`app.update()` 从 8.3 涨到 14.5ms 是这段
升温的直接结果 —— 频率被压下来了,但如上所述没吃到帧率。

**注意读数条件**:全程插着电、电量 100%。充电本身就是热源,拔电跑的数字会更低;
反过来,夏天户外或叠上其他负载会更高。这份读数只说明「不会热失控」,不是上限。

## 三、Adreno 的半透明坑没有复发

本仓踩过一次:`AlphaMode::Blend` 的小元素在这块 GPU 上整片不显示(桌面正常)。
点云因此分平台 —— 桌面 `Blend` 画软边发光圆点,安卓 `Mask` + 0.5 门槛画硬边
(见 `crates/render3d/src/cloud.rs` 的 `ALPHA_CUTOFF`)。真机上六档预设全部正常出图,
包括透明度最低的星河档(它的粒子 alpha 只有 0.16~0.9,曾担心被门槛整层丢掉)。

## 四、这一轮真机上抓出的缺陷

**物体类预设在竖屏左右出画。** 星球与唱片是被相机取景的一个物体,而透视投影固定的是
**垂直**视野 —— 横向可视 = 纵向 × 长宽比。竖屏 0.45 的长宽比下横向只剩不到一半,
球体两边被切掉。桌面上看不出来(窗口长宽比 0.9)。

修法是 `cloud::object_scale`:物体类那三档按长宽比再收一档,横屏不动。**不后撤相机** ——
那会把铺满视野的两档(封面、星河)缩成看不见的点,这条在 `crates/render3d/README.md`
末尾有专门一节记着,是更早一次真机实测的结论。

## 五、还没测的

- 拔电跑的读数。
- 32fps 与 66fps 那两档的分界。第一节给了「屏幕在 60/120Hz 间切、帧成本刚好越过
  vsync 截止线」这个解释,但没验:锁住 `min_refresh_rate` 再各测一轮才算数。
- 更长时间(半小时以上)会不会进第二档降频。
- 涟漪与拖动旋转的手感:真机上能点,但观感没有系统评过。
- 其余五档预设的逐档耗时:只量了封面档,那是粒子全部可见、最贵的一档;
  虚空档理论上最便宜(全部丢弃),没单独量。
