# docs/note

长篇笔记，分两类：操作手册(怎么构建、怎么同步 fork、怎么测量)和调查记录(一个现象查到了什么、
为什么这么定)。一篇讲一件事，结论写在前面，比 `docs/lesson/` 的单条经验长，也不像
`docs/adr/` 那样只记已经做出的架构决定。

不放：待办(在 forge 的 issue 上)、术语(`CONTEXT.md`)、架构决策(`docs/adr/`)、UI 硬规则
(`docs/design.md`)。

笔记里写到的文件路径、命令和选项名要跟代码对得上，对不上就在同一个变更里改掉。

- 操作：`dev-workflow.md`、`build-apk.md`、`fork-sync.md`、`server-image-release.md`、
  `desktop-sync-measurement.md`(多实例同步的静音测量，#138 xrun 调查的结论)
- 调查与方向：`android-frame-pump.md`、`desktop-exit-abort.md`、`cover-cloud-on-device.md`、
  `animated-background-and-compute.md`、`visualization-surface-and-audio.md`、
  `slint-bevy-architecture-and-direction.md`、`vision.md`
