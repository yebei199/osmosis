# audio/src/sync

同步播放：把「这一刻该放到媒体的哪里」变成真实出声的位置(#137 ⑤)。多台设备各自拉流，
跟同一条时间线，靠这一层对齐到毫秒级。

- `timeline.rs`:时间线的形状，即锚点(本机单调时钟的某一刻，媒体该在哪)、在不在放、从哪一刻起出声，
  以及「某一刻媒体该在哪」的换算。
- `follower.rs`:每一块输出开头做一次决定，决定取决于误差大小:
  - 大到要跳：能往前丢的就丢，丢不动就 seek;
  - 小的：用 ±0.1% 以内的速率慢慢追;
  - 跳过之后先静音，对齐了才放出来。
  这部分是纯规则，不碰声卡。
- `source.rs`:`SyncSource`,一个 rodio `Source`,包在真正的媒体(`Feed`)外面。
  - 它知道自己吐出去的每一帧是媒体的哪一帧，所以位置、跳转、暂停都归它，不归 rodio 的 `Player`。
  - `Feed` 能把「暂时没数据」和「真的静音」分开：欠载时位置不能往前走。

它**不做**的：
- 不开声卡：每块输出第一帧的呈现时刻由输出后端(`../output`)报进来;
- 不校时：时间线已经换算成本机单调时钟再交进来，校时在 `syncplay` 那一层;
- 不决定下一首。

机制来自 #137 ② 的原型(`experiments/synctest`),在那里经声学实测，电脑加手机做到稳态
|偏差| p95 为 2ms。产品里没有照搬原型代码：原型从内存里随机读媒体，产品的媒体是顺序拉的流，
跳转要经 `Feed::seek`。
