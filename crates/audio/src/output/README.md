# audio/src/output

输出后端：自己打开声卡流，从 rodio 的混音器(`MixerSource`)拉采样。每一块开头算出这一块第一帧
真正出声的本机时刻(`CLOCK_MONOTONIC`,纳秒),报给同步层(`../sync`)(#137 ⑤)。

之所以不再用 rodio 自带的设备，是因为它把 cpal 回调里的时间戳直接丢掉了。安卓上即便不丢也没用：
cpal 的 AAudio 后端给出的两个时刻不是同一个时钟，相减没有意义(#137 ⑤ 调查)。

- `cpal.rs`:桌面。呈现时刻 = 回调那一刻的单调时钟 + cpal 给出的 `playback − callback`
  (ALSA `snd_pcm_status` 的 delay)。
- `aaudio.rs`:安卓，直接用 NDK AAudio。呈现时刻 = `getTimestamp` 给出的「第 P 帧在 T 时刻出声」
  换算到这一块第一帧。
  - 流刚起来那几块拿不到时间戳，这时退回「现在 + 缓冲长度」估算。
  - 路由一换(插拔耳机、连蓝牙)流会断开，由持流的那条线程关掉重开。
- `rtkit.rs`:桌面 Linux 把送声线程升成实时(#192)。回调第一块交出线程号，持流线程经 zbus 请
  rtkit 按它允许的上限升级(先设 `RLIMIT_RTTIME`),每开一次流做一次;升不上去记一行警告，播放照常。
  不用 cpal 的 `audio_thread_priority`:那条走 C 的 libdbus。
- `route.rs`:此刻从哪条路由出声(扬声器/蓝牙/有线)。多台同步的合同只校准过扬声器，界面据此把
  别的路由标成「未校准」。桌面读 PipeWire 默认 sink 名(先问 `wpctl`,没有再问 `pactl`,都没有就报未知)，安卓经 JNI 问 `AudioManager`。
  查询在后台线程里跑，同一时刻最多一个，每条命令限时，超时就杀掉回收;调用方只读快照，从不等它。

两个后端都把流关在一条专属线程里：流对象不跨线程，重开也在那条线程上做。

桌面 cpal 的偶发后端错误由设备自行恢复；一秒内连续八次后端错误且没有成功数据块时，
标记流已断，交持流线程关流重开。成功数据块、跨过时间窗和 xrun 会打断错误串。
xrun 继续只计数，设备失效或配置作废仍立即标坏。错误回调只更新状态，日志由持流线程汇总。

持流线程先丢掉坏流并清掉旧呈现配对，再按 250ms、500ms、1s、2s、4s 封顶的间隔重试。
新流稳定一秒后恢复初始重试预算。回调错误和开流失败共用一秒日志窗口，保留累计计数与最近
开流失败原因；重复的开流失败也不会逐次写日志。等待期间仍通过通道处理停止信号。

暂停(或跟着的时间线暂停)满 30 秒，那条线程就把流关掉，让声卡与 PipeWire 图能休眠;要出声时
(按了播放、拖了进度条、时间线放起来)`Player` 叫醒它马上重开(#138)。重开之后的第一块照常报呈现
时刻，组里的跟随端据此静音追赶再出声，和刚加入时一样。流关着的那段时间，持流线程每 20ms 替声卡把混音器拉一段、丢掉。当初是因为 rodio 换源(`Player::clear`)
要等拉采样的一方把旧源摘掉才返回，没人拉就会把界面线程卡死;如今换源归 `../player/deck.rs`,不再等，
空拉留着无害。暂停着的时候同步源只吐静音、不消耗媒体，
所以空拉是安全的;要出声时则先开流，不空拉。

不做：采样率转换与混音(归 rodio 的混音器),对时间线(归 `../sync`)。
