# render3d

3D 桥:用 **bevy**(0.19 稳定版)在**共享的** wgpu-29 device 上离屏渲染,
播放页每帧产出一张 `slint::Image`(当前效果画在透明底上),交给 UI 层合成。

## 为什么存在 / 边界

主体是 Slint 应用,本 crate 只负责「Slint 做不来的 3D 效果 / 小游戏」那一块。

- **桌面 / android 入口硬依赖它**,web / ios 永不碰 —— 由 `xtask boundaries` 守住。
  曾经它是个 `bevy-3d` feature,那时有个 3D 演示页可关;演示页删掉之后播放页的粒子、
  卡墙与导航选中器全长在这里,关掉就只剩静态版式,开关遂取消(见 `docs/adr/0011`)。
- `ui` 对 bevy / wgpu 一无所知:本 crate 把渲染结果作为 `slint::Image`
  经 `ui::run_with_renderers` 的 seam 交过去(见 `crates/ui`)。
- 要加新 shader 前先看
  [`docs/note/animated-background-and-compute.md`](../../docs/note/animated-background-and-compute.md):
  fragment 与 compute 的分界(判据是 scatter)。那篇里关于省电门的段落写于
  第一代按需渲染;2026-09-27 起是 `docs/adr/0035` 那一套(唤醒收成一处)。

## 关键架构约束(见计划 `bevy-serialized-dove`)

1. **共享 device**:instance/adapter/device/queue 由本 crate 自建(Manual),
   同一套既注入 Slint 的 `require_wgpu_29`,也注入 bevy 的 `RenderCreation::manual`。
   Slint 只能采样属于自己 device 的纹理,所以共享是硬性要求。
2. **事件循环归 Slint**:bevy 禁用 `bevy_winit`、无头运行,由 Slint 的 `Timer`
   每帧驱动 `app.update()`,绝不调 `App::run()`。
3. **wgpu 版本对齐**:bevy 与 slint 必须共享同一 wgpu 大版本(现为 29,Cargo.lock
   里实为单份 `wgpu 29.0.4`)。升级任一方前先核对,否则 `wgpu::Texture` 类型不兼容。

## 导航液态玻璃选中器(`navglass.rs` + `navglass.wgsl`)

导航条的背景由一个**不经 bevy** 的独立全屏 fragment pass 画:底色 + 一层微极光,
外加一块会在 tab 之间「流动」的圆角矩形 metaball —— 头(快)、尾(慢)、小水滴(最慢)
三个位置都朝当前选中槽中心移动,行走时 smooth-union 拉出胶着的颈,静止时重合成单块,
颈那一档折射自绘的极光背景。

三球还带一个整体缩放 `ball`:侧栏底部的个人与设置是 glass 圆钮、不在轨道上,选中它们时
水滴化掉(半尺寸与融合半径一起缩,不然球没了颈还在,收尾会剩一团糊影)。

宽版式的左侧栏与紧凑版式的底栏共用这一条 pass,差别只有移动轴:侧栏沿 y,底栏沿 x
(`horizontal`)。三球位置只带移动轴坐标,固定轴的中心由 ui 侧算好(底栏的图标被手势条
inset 顶上去了,不在纹理正中);半尺寸一边按格长、一边按条的厚度取,自绘背景那三团极光
的 uv 也跟着转置,否则在扁条上会挤成一坨。

为什么不长在 bevy 里:选中器是纯 2D 玻璃,没有 3D 场景/ECS。而 texture→`slint::Image` 的桥
(`Image::try_from(wgpu::Texture)`)本就与 bevy 无关,故在 `Scene` 暴露的**同一块共享 device**
上自起一个 pass 即可。思路见 `docs/note/slint-bevy-architecture-and-direction.md` 第八节。

- 几何(槽位、条尺寸、移动轴、三球动画位置)由 `app.slint` 的 `nav-*` 属性给出,**是唯一真相**;
  由 apps/* 在 seam 处翻译成 `NavParams`(POD,镜像 `ui::NavGlassControls`)。
- **只在切 tab 的转场期间重算纹理**(判定在 `ui::nav_glass::nav_transition_active`),静止时 Slint
  复用上一帧 —— 这是工作量缓存;转场本身由 Slint 的动画出帧(按需渲染,`docs/adr/0035`)。
  **明暗主题也在判据里**:导航背景是本 pass 自绘的,采不到背后的像素,
  换了主题必须重画一次,否则要等下一次切 tab 才跟上。
- 分工:玻璃视觉在 shader;图标、标签、hover/点击仍由 Slint 画在上面。非 GPU 构建 `nav-bg`
  为空,两种版式都退回 Slint 平底 + `NavItem` 自带高亮(渐进增强)。

## 音乐页卡墙(`wall.rs`)

音乐页主视图(adr/0025):曲目封面卡在深度上散开,拖动往任意方向翻找、双击
dolly 进播放页。几何与动力学的真相全在 `ui::wall`,那边把每张卡**合成完的
世界位姿**(环面回绕也已折算进去)经 seam 传来,这里只摆位姿、灌卡面纹理、
渲一帧。相机因此永远在原点,不带平移。

- 卡是 unlit 的 `StandardMaterial` 方片,圆角、描边、投影都由 ui 侧烘进纹理
  (`ui::wall::bake_card`),不为它们开自定义材质。纹理比卡面四周各大一圈
  (`CARD_PAD`)好装投影,方片跟着按同比例放大。世界单位 = 物理像素,
  相机距 z=0 平面为 CSS 意义的
  `perspective`(随容器宽缩放),竖直视野由目标高反推 —— 与 ui 侧
  `wall::project` 严格同构,命中测试与画面不会各说各话。
- 卡墙实体与相机挂在渲染层 1,与播放页的两个效果互不可见;两条渲染入口互相关灯,
  谁激活谁渲,不会白画一整面。
- **正在放的那一张**换上 `foil.rs` + `foil.wgsl` 的闪卡材质:彩虹干涉条纹
  加一道扫光,按帧计数常驻流动,靠底图 alpha 收在卡面内(投影那一圈不参与
  发光)。换材质靠增删 `MeshMaterial3d` 组件 —— 一个实体同时挂两种会被画两遍。
- 每帧由 `ui::wall::drive` 组帧;墙在动或有卡面要传时必渲,静墙只在活跃期内照渲
  (`docs/adr/0035`)。无 GPU 构建
  根本不会建 `Scene`,音乐页退回列表(web / iOS)。
- 透明度**分平台**:安卓 `Mask(0.5)`,桌面 `Blend`。2026-08-30 在努比亚平板上
  试过两端统一走 `Blend`,整面墙一张卡都画不出来(同批曲目在列表里封面齐全,
  卡墙纹理也照常导入),换回 `Mask` 立刻正常 —— adr/0012 记的 Adreno 坑
  换了设备依然在。代价是安卓上没有投影:它的峰值 alpha 0.42 整段低于门槛,
  被 alpha 测试丢掉;圆角也从软边变硬边,描边不受影响。

播放页曾有一条反馈式 warp pass(全屏拖影 + 频谱环),环形播放键的彩虹圈也是它;
两者连同光带按钮那条 pass 已随 `docs/adr/0038` 删除,播放页最底层换成 ui 侧算好的糊封面。

## 播放页的效果与驱动入口(`effect.rs` + `Scene`)

`render_viz_frame` 是本 crate 里 bevy 侧播放页唯一的驱动入口;主相机清屏透明,场景图
铺满整窗、叠在糊封面背景之上。场景里有两个**效果**(`docs/adr/0041`),同一时刻只有一个
可见:封面实物(默认,`sleeve*`)与封面点云(`cloud*`)。两摊实体都常驻、都收封面,
另一摊挂 `Visibility::Hidden`,不进任何渲染阶段;切换不重建、不等封面。拖动交给当前
那一个:点云转、松手滑行;封面实物偏转、松手回弹。

**主体在宽版式偏左、紧凑版式偏上,由相机移轴做**(`camera::lens`,bevy 的 `SubCameraView`)。
从前是 `.slint` 把整张图往左推两成窗宽,图只有一个窗宽,右边那条于是没有任何 3D 内容。
移轴与整张平移逐像素相同,点云观感不变;纵向移轴时视野要按整幅加高的倍数放大,否则窗里
的东西跟着放大(单测钉着)。bevy 的视锥剔除仍按不移轴的那一幅算,所以两个效果的实体都挂
`NoFrustumCulling`。

## 封面实物(`sleeve.rs` + `sleeve/` + `sleeve.wgsl`)

封面印在一块薄封套上:圆角、半圆倒角、厚度为边长的 3.4%,正面与倒角靠正面那半圈按 xy
平面投影取封面(印刷包边)。一座「台面」实体挂着封套、它的倒影、换歌时退场的那一张与其
倒影、地面;台面随视口整体缩放(`motion::stage_scale`),并往前倾约 9° —— 等价于相机略微
俯视,但不挪相机(点云要正对着看)。

- **一份着色器三种画法**(`kind`):封套、倒影、地面。光是写死的一盏柔和主光加半球环境光,
  不接 bevy 的 PBR —— 那要阴影、prepass 与整套光照绑定,这里只要「一盏灯照着的纸板」。
  正面一道很淡的斜向光泽随偏转滑过,高频起音时闪一下;倒角一圈边缘光由平滑过的低频推亮。
- **跟着音乐的是事件,不是电平**(`beat.rs`,纯状态机,有单测):低频起音(电平高过自己 0.4s
  的滑动平均 1.4 倍以上、且至少高 0.06、不低于 0.12,不应期 0.12s,边沿触发)给封套一下冲量 ——
  峰值放大 2.5%、点头约 1.3°,临界阻尼弹簧(ω = 26,按闭式解推进)200ms 内收回,不往后缩;
  中频平滑过的响度(起 0.8s、落 2.5s)把呼吸的摆幅从 1 倍放到最多 2.2 倍;高频起音只让光泽
  闪一下(0.1s 衰减)。没有一样逐帧跟着电平走 —— 那会是持续的抖。鼓点与摆幅叠在呼吸与拖动之上,
  换歌交接那 0.8s 不起新鼓点;不在显示时全部清零(起音检测重新立平均,不拿过期的平均比出假鼓点)。
- **倒影是镜像网格**:y 取反、绕序反转烘进几何,实体变换因此是正常旋转(四元数 `(−x, y, −z, w)`,
  平移关于地面翻过去),背面剔除照开。着色器把翻到地面以上的那截剪掉(拖动转出地面时会有)。
- **半透明分平台**:地面与倒影在桌面走 `Blend`,安卓走 `Mask` 加 4×4 有序抖动 —— 上面卡墙那段
  记的 Adreno 坑还在。桌面上地面与倒影的先后靠 bevy 按包围盒中心排序,所以地面往远处
  铺得很深,中心明显落在封套后面(`mesh.rs` 里有编译期断言)。
- **运动**(`motion.rs`,纯函数与小状态机,有单测):呼吸 ±3°/±2°(响的段落按上一条放大);拖动橡皮筋上限约 40°/25°,
  松手由欠阻尼弹簧拉回(冲过头一点);换歌交接 0.8s,旧的加速甩向左后方,新的从它后面落位。
  先换歌、封面后到时落位的是空封套,封面到了显影,不再甩第二次。不在显示时收到的换歌直接
  落到终态(`Sleeve::settle`),切回来不补放一次过期的交接。
- 旧封面纹理不手动删:点云的「上一首」与退场那张各自持有句柄,随最后一个句柄放掉而释放。

## 播放页封面点云(`cloud.rs` + `cloud.wgsl` + `Scene`)

播放页的第二个效果(issue #22,默认是上面的封面实物):**当前曲目的封面被采样成
96×96 个方块**,每块取封面上对应像素的颜色,整片随声音起伏。封面那一块之外按同一格距
铺满整个视口(`cloud/field.rs`),见下面「铺满视口」一条。行为照抄参照物 Mineradio 的
`02-visual/00-pointer-cover-particles.js`。下面几条里关于六档预设、圆点、Blend 的段落是
历史:预设只剩「封面」一档且子预设 seam 已收掉,粒子早换成立方体、两端都走 alpha 测试。

关键结构决策在 [`docs/adr/0012`](../../docs/adr/0012-cover-point-cloud-is-one-mesh-in-the-bevy-scene.md):
点云是 bevy 场景里的**一个 mesh**,不是三万多个实体,也不是又一个独立 wgpu pass。

- **铺满视口**(`docs/adr/0041` 第五节):封面那 96×96 格位置、大小、uv 一概不动,外面按视口在
  点云平面上框住的那一块(镜头移轴、长宽比、版式都算进去)往四边补格,外加「方块往后退 0.25
  也还铺得满」的余量与两格边。外圈 uv 越出 0..1,着色器据此取封面边缘外延、取高几级 mip 的
  糊色(`scene/mips.rs` 在上传时生成 mip 链),亮度从 0.5 往视口边压到 0.12,起伏弱到 0.35;
  换歌的错峰相位接着往外涨,外圈比封面的角更晚落。视口变了、而且稳住 0.2s(墙上时间)才
  只换一份 `Mesh3d`,多出来 8 格以内不缩;实体、材质与过渡都不动。数量:16:9 宽版式
  194×112 ≈ 2.17 万颗,9:20 紧凑竖屏 96×119 ≈ 1.14 万颗(只封面时 9216)。
- `cloud.rs` 是纯计算加胶水:`band_levels` 把频谱行拆低/中/高三段;`cloud_vertices`
  烘出那份只随视口重烘的顶点缓冲(每颗粒子四个顶点拼一个方片,带格点 uv、角偏移、
  逐粒子随机数);`CloudMaterial` 是自定义材质,顶点布局把角偏移借在法线属性位上。
  单元测试盯的是网格本身(四角齐全、uv 不贴边、索引不越界),位移与观感走真实像素验收。
- `cloud.wgsl` 里是全部运动学,按 `preset` 分六档(issue #26):**封面**(中频两层
  simplex 起伏 + 高频抖动 + 低频呼吸,全部只推 z)、**滚筒**(uv.x 绕成管壁、uv.y 沿轴
  流动)、**星球**(uv 映成球面 + 自转)、**虚空**(整层丢到相机背后)、**唱片**(极坐标
  圆盘:盘心采封面、盘面画黑胶纹路)、**星河**(5.65 条极光带 + 一层纵深尘埃)。
  各档只返回一个 `Placement`(位置/采样 uv/染色/透明度),主函数统一投影 —— 加档不必
  再动主函数。参照物的第七档「安魂」要一份骷髅点云资产,不是算法,没做。
- 尺度分两类:**铺满画面的两档**(封面、星河)自己就在最终尺度上;**物体类三档**
  (滚筒、星球、唱片)按相机距离对齐(`object_scale`)—— 它们是被取景的一个物体,
  按平面倍数放大会大到糊在镜头上(实测)。
- 方片在**视图空间**摊开,粒子因此永远是正圆而不是随相机变斜的菱形;摊开量用世界
  单位而不是像素,点与格距同比投影,窗口怎么变比例都不动。
- 指针交互(issue #25):划过起涟漪(12 路环形缓冲,`Ripples`),按住拖动转点云
  (`Spin`,带松手惯性)。转的是**点云自己**不是相机 —— 相机是两个效果共用的。
- CPU 每帧只改材质的一块 uniform(时间 + 三段电平 + 视口在封面 uv 里的四边),几何只在视口变了时重烘。
- 透明度分平台:桌面 `AlphaMode::Blend` 画软边发光圆点,安卓 `AlphaMode::Mask` 画硬边。
  小米13(Adreno)上半透明小元素整片不显示是本仓踩过的坑。
- 材质关掉 prepass 与阴影:两者都会拿**默认**顶点着色器再跑一遍这份 mesh,而我们的
  顶点布局只有 `cloud.wgsl` 读得懂。着色器随二进制内嵌(`embedded_asset!`)——
  应用无头运行,没有 `assets/` 目录。

早先这里是一层与封面无关的**浮空尘埃**(1300 颗五色小球绕卡片飘),照抄的是参照物
同一目录下的 `01-float-skull-backcover.js` —— 那只是它封面粒子系统背后的配菜。
主体做出来之后配菜删掉,`band_levels` 是唯一留下的部分。

## 相机不随视口长宽比后撤

透视投影固定的是**垂直**视野,水平视野 = 垂直视野 × 长宽比,所以视口一竖(手机竖屏、
桌面拖窄的紧凑版式,长宽比可低到 0.26)横向排开的内容就会出画。这里**刻意不**为此后撤相机:
点云与视口一起变窄就好,后撤只会把粒子缩成看不见的点 —— 小米13 竖屏 aspect 0.45 要后撤
2.2 倍,真机上实测粒子直接消失。相机恒在 `BASE_CAMERA_POS`,窄视口下让点云自然裁掉左右;
封面实物是一个有边界的物体,自己按视口收尺寸,不出画。

早先为 3D 演示页写过一个 `pullback(aspect)`(参考长宽比 / 当前长宽比,封顶 4 倍,整体缩放
位置向量以保住俯视角),演示页删掉后它没有消费者了,一并删除。
