# playback

放哪一首,以及放的时候条上发生什么:控制条的绑定(`controls`)、一条播放
意图的派发(`dispatch`)、起播与切歌的传输层(`transport`)、自动续播与
下一首的预取(`advance`)。

与 `../list`、`../feed` 的分法:那两个管「摆出哪些歌」,这一组管「放哪一首」。
解码与设备归 `crates/audio`,队列规则归 `app-core`。

组那一侧(#142,`docs/adr/0032`)另有三块:照服务端全局状态对准本机播放(`group`)、
输出设备那一排的选一台与「+」(`outputs`)、本机手上那一版执行副本的身份(`execution`)。

## 一条播放意图只有一个入口

用户按下去的那一下分三段走,`dispatch` 是中间那一段,也是唯一定夺的地方:

| 段 | 在哪 | 干什么 |
|---|---|---|
| translate | `controls`、`media`、`queuepage` 各自的回调 | 组装整批,翻成一条 `Intent`。不知道这一下会落在哪 |
| dispatch | `dispatch::dispatch` | 本机在组里 → 发组意图(`POST /group/*`);不在 → 本机执行 |
| execute | `dispatch::execute` | 本机的执行体:命令落到本机播放器上 |

**判据只有一个:本机在不在组里**(在 `members` 里)。在组里时,不管本机出不出声,
点歌、⏯、上下首、拖动、随机、循环都只改服务端那一份全局状态,本机播放器由 `group`
照状态去对准 —— 不直接动它。请求失败一律提示一句,不静默丢弃;同一首的点歌意图还在路上
就不再发。

## 本机与组**不**相同的那几处

统一掉任何一条都会悄悄改变用户看得见的行为,所以逐条钉在测试里
(`../tests/dispatch.rs`、`../tests/group.rs`):

- 本机播放器已空时按播放是**重播**,不是 `Resume`(`local_toggle`)。组里没有这一档 ——
  ⏯ 按全局状态的「在不在放」翻。
- 连点去重读的是**本机**的 playback,所以只在本机分支上问。
- 拖进度在组里按组里那一首的曲长换算:只当遥控器时本机手上没歌也拖得动。
- **音量每台各自调**,在组里也落在本机、不发意图;存盘归真正改变响度的那台。
- 在组里本机不自己续播、不自己上报起播:放哪一首只听全局状态,起播由服务端记。

跳转是异步的:请求送到解码线程后立刻挂「缓冲中」,落地与失败由每秒那趟轮询
取回(`controls::push_seek_state`)。
